# PromptDog 工作台 · 原型与前端构建规范 v1.1（2026-09-08）

> 读者：接手做原型或前端的 agent（Claude Design / Claude Code）或人。它定的是要画哪些屏、每屏有什么、怎么交互、按什么原则判断好坏、参考谁；不定商业目标（那在 `产品定义.md`），不定做的顺序（那在 `stories.json`）。数据契约在 `flow.schema.json`，示例数据在 `flow.py` 的 `NODES` / `EDGES`。HTML 版《设计文档》是同一内容的展示稿：`promptdog-design-spec.html`。

**怎么读**：§1–§3 建语境，§3 的八条原则是后面所有判断的依据；§5 与 §6 是要做的东西，§6 流程画布是重心；§8 告诉你从哪些产品借什么、不借什么；§10 是验收；§11 是要产品负责人拍板的事，遇到就停下来问，不要替他决定。

**边界**：沿用现有视觉语言（琥珀主色、暖白底、深色侧栏，§7），不做品牌重塑；所有业务数据都是示例，必须标注；不设计登录、计费、权限；不做后端与托管执行。

## 1 产品背景

PromptDog 是装进用户 AI（Claude Code / Codex / WorkBuddy）里的技能包：一句模糊需求 → 判复杂度 → 带推荐默认值的选择题 → 交付能直接上岗的 Agent 资产包（工作狗，住在犬舍里，自带启动指令、复盘飞轮、回归测试）。

工作台是它的产品界面：一句话造工作狗、犬舍、组件库，以及组织流程画布。画布是公司流程的地图：每个节点是人、工作狗、技能、行业 know-how 或数据系统；三种标记回答三个问题：卡在哪、缺什么、要打通什么。**画布是中心，聊天窗口不是。**

运行模型：工作台是壳，引擎是用户自己的 Claude Code / Codex。画布产出资产包、启动指令与 `验收清单.json`，不自带执行。楔子场景：投标流程。

## 2 用户与场景

| 角色 | 要什么 | 主屏 | 成功的样子 |
|---|---|---|---|
| 流程负责人 / 老板 | 30 秒看懂：哪些自动、人在哪、卡在哪、缺什么、打通什么；拍板 | 07 画布 · 汇报模式 | 不用别人解释就能指着图说「先打通招标平台」 |
| 搭建者（PM / 售前主管 / IT） | 画现状，塞 AI，配组件，打通系统 | 07 编辑模式，02b，06 | 一小时内从一句话到一张可建的目标流程 |
| 执行者（商务 / 售前） | 让工作狗跑起来，出问题知道退回哪步 | 05 上岗，04 犬舍 | 一条启动指令跑到交付，只在人审人定处停 |
| 专业角色（财务 / 法务 / 领导） | 只在人审、人定节点出现 | 05 的人工确认点、通知 | 看摘要与变化清单就能过或退回 |

五个核心场景：① 一句话造工作狗（01 → 02 → 03）② 画流程找卡点（07）③ 打通与补齐（07 属性面板、诊断）④ 工作狗上岗运行（05）⑤ 复盘回流（04、07 运行态、10）。

**从 0 到 1 的使用逻辑**（`使用逻辑.md`）：第一周只做一条流程、一只狗——画出现状（01 → 07，30 分钟）→ 建第一只狗（02 → 03 → 04，30 分钟）→ 上岗一次（05，1 小时，只在递交前停）→ 复盘（04 → 10，15 分钟）→ 回到图上（07，10 分钟）。用户每一步只做纠错：说编号。首次进入由屏 00 引导。

## 3 八条设计原则

做任何屏之前先问：这个设计服务哪一条？答不上来就别加。

| # | 原则 | 一句话 | 落点 | 怎么验收 |
|---|---|---|---|---|
| 1 | 先读懂，再动手 | 老板 30 秒答五问 | 泳道 + 三种标记 + 顶栏五个数字；汇报模式只留这些 | 3 个没看过的人 30 秒答对 4 问 |
| 2 | 两条线不混 | 控制线与数据线分开画 | 五种线型，线上写产物名 | 任一条线不看图例能说出是什么 |
| 3 | 节点即组件，组件即资产 | 工作狗是子图，选几个节点能打包成新狗 | 组件库、双击钻取、框选打包、入犬舍 | 打包后的狗能拖进另一条流程复用 |
| 4 | 类型约束替代规则说明 | 端口按产物类型着色，不兼容连不上 | 端口颜色、拖线变红、连线面板 | 不读文档也连不出无意义的线 |
| 5 | 一张图三种看法 | 目标态 / 对照现状 / 运行态是同一张图的三个镜头 | 顶栏「对照现状」「试跑」；节点上的原：人做 / 手工搬 / 新增 chip | 切镜头节点位置不变，只变标注 |
| 6 | 人机边界显式且可拖 | 跨泳道就是决策 | 人 → AI 泳道 = 要自动化并标缺口；AI → 人泳道 = 改人审；不可逆前的人定节点受保护 | 拖一次就懂，不需要说明文字 |
| 7 | 默认值先行，卡片是纠错窗口 | AI 先给图，人只纠错；没有空白画布 | 一句话生成草稿；诊断建议一键「应用」 | 一句话到草稿 ≤ 60 秒，零输入也有结果 |
| 8 | 最短路径 | 创建与连接一个动作，一切可撤销，不出模态框 | 端口拖到空白即新建并连上、双击搜组件、右键菜单、撤销、快捷键 | 加一个连好线的节点 ≤ 2 个动作 |

与方法论的关系：原则 7 = SKILL.md 的预填交付；原则 6 的人定保护 = 人工确认点只在不可逆动作前；原则 5 的运行态 = 复盘飞轮。冲突时以 SKILL.md 为准。

## 4 信息架构与导航

| 侧栏分组 | 条目 | 去哪 | 说明 |
|---|---|---|---|
| 顶部动作 | 造一只工作狗 | 01 | 唯一主按钮，琥珀实底 |
| 我的数字员工 | 提示狗、合同审查、标书撰写、内容营销、竞品分析… | 提示狗 → 01；工作狗 → 05 | 新建的带「新」徽章；按最近使用排序 |

| 犬舍 | 全部工作狗、组件库、复盘与回归 | 04、09、10 | 复盘有待处理时右侧琥珀圆点 |
| 底部 | 我的工作区 | 设置（不设计） | 占位 |

顶栏承载当前对象的上下文：标题、状态 chip（判级 / 轮次 / 版本）、右侧动作。画布页顶栏 = 五个数字 + 模式开关（撤销、对照现状、产物、试跑、按这个建）。一屏只有一个主按钮。

全局模式四种，互斥，切换不改位置只改标注：编辑（默认）/ 对照现状（叠加 chip、压暗未变节点）/ 试跑（按顺序点亮自动节点）/ 汇报（隐藏组件库与属性面板）。

## 6 流程画布规格

### 6.1 布局

三栏 + 三条泳道。尺寸基准 1920×1080：侧栏 240，组件库 200，属性面板 292，画布内容区 1220×1024，缩放 50%–160%。泳道分界 y=440 与 y=720：AI 在上，人在中，数据与系统在下。组件从左侧库拖入成为节点；人的节点琥珀边框；数据系统节点虚线；指向它的蓝色虚线 = 现在靠人搬数据；右栏无选中时是诊断，选中后是该对象的属性。

### 6.2 对象模型

以 `flow.schema.json` 为准，摘要：

| 对象 | 关键字段 | 说明 |
|---|---|---|
| node | id, kind, role, name, sub, x, y, flag, note, fix, was, target, owner, sla, notify, method, dir, reuse, src, pack, children | kind 五类 human / dog / skill / know / data；role 三档 auto / review / decide（数据节点为空）；flag 四态 ok / block 卡点 / missing 缺口 / pending 待打通；was 记原来怎么做（human / manual / new）；target 是应用建议后的状态；children 是子图 |
| edge | id, from, to, kind, label, dtype, contract | kind 五种 seq / data / pending / loop / back；label 是产物名；dtype 六类 file / struct / text / decision / event / sys；contract 写字段与格式 |
| lanes | mode, bands | role（默认）或 dept；同一份节点只换分带规则 |
| flow | name, essence, version, nodes, edges, lanes | essence 是那句「本质」；撤销栈、当前模式、缩放是界面状态，不入文件 |

|---|---|---|
| 组件库 | 搜索框；五组：工作狗、技能、行业 know-how、数据与系统、人；底部「新组件（占位缺口）」 | 每项带拖动把手、类型圆点、名称与一句说明；工作狗显示环节数；缺的 know-how 标「缺 · 待沉淀」 |
| 诊断（默认） | 卡点 / 缺口 / 待打通三行各带节点 chip；重构建议列表，每条可「应用」；拖法提示；重置示例 | 数字与顶栏一致；点 chip 选中节点；建议由标记自动生成 |
| 节点属性 | 名称、说明、谁来做、状态、备注（卡在哪 / 缺什么 / 要打通什么）、怎么解、输入、输出、删除 | 分类型附加字段见下；有 target 的显示「应用建议」 |
| 连线属性 | A → B、流动的产物、产物类型、关系、数据契约、删除 | 待打通改成数据即变实线 |
| 构建预览 | 环节（AI 泳道按顺序）、工具清单（数据与系统）、人工确认点（人定）、交付前必须解决（缺口与卡点）、一句总结 | 缺口和卡点不解决也能建，写进未达标清单；导出 = 资产包目录 + `验收清单.json` 草稿 |
| 汇报模式 | 本质一句话、五问数字、放大画布、导出 PNG / PDF | 隐藏组件库与属性面板；不可编辑 |

分类型附加字段：人 → 负责人 / 部门、时限、通知渠道；工作狗 → 子流程环节数、复用于 N 条流程、打开子流程、版本；技能 → 复用于 N 只工作狗、改一处全部同步的说明；行业 know-how → 来源（行业库 / 你的材料 / 待沉淀）；数据与系统 → 打通方式（接口 / RPA / 文件 / 人工）、方向（读 / 写 / 读写）、系统负责人。

### 6.6 泳道语义规则

| 拖动 | 结果 | 提示文案 |
|---|---|---|
| 人的步骤 → AI 泳道 | 变技能节点，自动，标缺口，记「原：人做」 | 「X」标为要自动化：还缺一个组件来做它（缺口） |
| AI 节点 → 人泳道 | 角色改人审，类型不变 | 「X」改为人审 |
| 步骤节点 → 数据泳道 | 弹回人泳道底部 | 步骤节点不能放进数据泳道 |
| 数据节点 → 其他泳道 | 弹回数据泳道 | 系统节点留在「数据与系统」泳道 |
| 部门泳道下跨道 | 改负责人 / 部门；跨道连线视为交接并高亮 | 交接 +1：卡点多长在交接处 |

### 6.7 空状态、边界与错误

- 没有空白画布。新建流程从一句话（由用户的 Claude Code 跑 PromptDog 流程重构模式产出 JSON 再导入）或模板生成草稿；真要空白，画布中央三个动作：从一句话开始、选模板、拖组件。
- 不兼容连线：拖到目标时线变红，松手不连，提示原因（「决定不能直接进数据系统」）。规则清单在 `flow.schema.json` 的 `x-compat`。
- 删除不可逆前的人定节点：二次确认，说明这是人工确认点规则。
- 无人回复时：任何卡片与确认都有默认路径；试跑与构建不因缺口停下，缺口进未达标清单。
- 子图内：新打包的狗至少两个环节；钻进去看到与顶层一致的泳道。

## 9 文案与语气

说人话，结果先行；判级算式、策略名默认收起。确认类文案写「我按 A 做了，不符再改」，不写「请确认」。按钮是动词：按这个建、应用建议、打包成工作狗、返回上一层。提示解释后果不是操作。标记名固定：卡点、缺口、待打通；线名固定：顺序、数据、待打通、回填、退回。示例数据标「示例」，缺事实用【待填】，不编造。

## 10 验收指标

| 指标 | 怎么测 | 目标 | 原则 |
|---|---|---|---|
| 五问 30 秒 | 3 个没看过的人看汇报模式 30 秒作答 | ≥4 问对 | 1 |
| 一句话到草稿 | 从导入 JSON 或模板到画布草稿出现 | ≤60 秒，零输入也有结果 | 7 |
| 修正次数 | 示例流程从草稿到「按这个建」的人工改动数 | ≤8 | 7 |
| 两动作新建 | 加一个连好线的节点的动作数 | ≤2 | 8 |
| 复用率 | 被两条以上流程使用的组件占比 | 示例 ≥30% | 3 |
| 卡点消除数 | 对照现状前后卡点数量差 | 投标示例 2 → 0 | 5、6 |
| 无人回复可跑完 | 不点任何确认，试跑与构建能否结束 | 能，缺口进未达标清单 | 7 |
