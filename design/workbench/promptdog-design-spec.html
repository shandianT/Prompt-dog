01文档用途与读法

这是一份给原型设计者的工作文档，读者是 Claude Design，或任何接手做原型的人。它不是 PRD，不定商业目标；它定的是：要画哪些屏、每屏里有什么、怎么交互、按什么原则判断好坏、参考谁。

怎么读先读 §2 到 §4 建立语境，§4 的八条原则是后面所有判断的依据。§6 和 §7 是要画的东西，§7 流程画布是本轮的重心。§9 告诉你从哪些产品借什么、不借什么。§12 是验收，做完对着它检查。§14 是需要产品负责人拍板的事，遇到就停下来问，不要替他决定。

边界：沿用现有视觉语言（琥珀主色、暖白底、深色侧栏，见 §8），不做品牌重塑；所有数字与业务数据都是示例，必须标注；不设计登录、计费、权限。

02产品背景

PromptDog 是什么。一个装进用户 AI（Claude Code、Codex、WorkBuddy 等）里的技能包：用户说一句模糊需求，它先判复杂度，再用带推荐默认值的选择题澄清，然后交付能直接上岗的 Agent 资产包。资产包叫「工作狗」，住在「犬舍」里，自带启动指令、复盘飞轮和回归测试。核心信条：让用户做选择题不做问答题；卡片是纠错窗口不是审批关卡；能简单绝不复杂；验收标准先于设计；循环必须有终点。

工作台是什么。PromptDog 的产品界面：一句话造工作狗、犬舍、组件库，以及本轮新增的组织流程画布。画布是公司流程的地图，每个节点是人、工作狗、技能、行业 know-how 或数据系统；三种标记回答三个问题：卡在哪、缺什么、要打通什么。

愿景一句话。公司未来的核心工作是组织流程的优化；agent 只是服务流程的执行体。所以画布是中心，聊天窗口不是。

已定 · 楔子场景

投标流程。跨销售、商务、售前、财务、领导五个角色，卡点真实，犬舍已有标书撰写 Agent。合同审查排第二。

已定 · 运行模型

工作台是壳，引擎是用户自己的 Claude Code 或 Codex。画布产出资产包加启动指令，不自带执行。托管执行放以后。

专业角色（财务 / 法务 / 领导）只在人审、人定节点出现，看到该看的就够05 里的人工确认点，通知看摘要与变化清单就能过或退回

五个核心场景

  1. 一句话造工作狗：首页输入一句话，判级，最多一轮选择题，交付资产包并入犬舍（01 → 02 → 03）。
  2. 画流程找卡点：把投标流程画出来或由 AI 反推出来，标出卡点、缺口、待打通，得到重构建议（07）。
  3. 打通与补齐：对系统节点定打通方式，对缺口配组件或新建占位，应用建议后看目标态（07 属性面板、诊断）。
  4. 工作狗上岗运行：启动指令一条跑到交付，人审人定处暂停，交付物实时生成（05）。
  5. 复盘回流：运行数据回到画布节点，改现状图，改版跑回归（04、07 运行态，待设计）。

04设计原则

八条，每条都有落点和验收方法。做任何屏之前先问：这个设计服务哪一条？答不上来就别加。

#原则一句话在原型里的落点怎么验收
1先读懂，再动手老板 30 秒内回答五问：哪些自动、人在哪、卡在哪、缺什么、打通什么泳道 + 三种标记 + 顶栏五个数字；汇报模式只留这些五问测试：找 3 个没看过的人，30 秒内答对 4 问
2两条线不混顺序线与数据线分开画，卡点和待打通只在数据线上，退回和分支只在控制线上五种线型（§7.3），线上写产物名任意一条线不看图例能说出它是什么
3节点即组件，组件即资产每个节点是可复用组件，工作狗是子图，选几个节点就能打包成新工作狗组件库、双击钻取、框选打包、入犬舍打包后的狗能拖进另一条流程复用
4类型约束替代规则说明端口按产物类型着色，不兼容的线连不上，新线自带默认产物与契约端口颜色、拖线变红、连线面板不读文档也不会连出无意义的线
5一张图三种看法目标态、对照现状、运行态是同一张图的三个镜头顶栏「对照现状」「试跑」，节点上的原：人做 / 手工搬 / 新增 chip切换镜头时节点位置不变，只变标注
6人机边界显式且可拖泳道有语义，跨越边界就是决策人的步骤拖进 AI 泳道 = 要自动化并标缺口；AI 拖进人泳道 = 改人审；不可逆前的人定节点受保护拖一次就理解，不需要说明文字
7默认值先行，卡片是纠错窗口AI 先给出图，人只纠错；没有空白画布一句话生成草稿；诊断建议一键「应用」从一句话到可用草稿不超过一分钟，用户零输入也能得到结果
8最短路径创建与连接是一个动作，一切可撤销，不出现模态框端口拖到空白即新建并连上、双击搜组件、右键菜单、撤销、快捷键加一个连好线的节点不超过两个动作
和 PromptDog 方法论的关系原则 7 就是 SKILL.md 的「预填交付」；原则 6 里的人定节点保护对应「人工确认点只放在不可逆动作前」；原则 5 的运行态对应复盘飞轮。原型不能违背这些规则，遇到冲突以 SKILL.md 为准。

顶栏承载当前对象的上下文：标题、状态 chip（判级、轮次、版本）、右侧动作。画布页的顶栏是数字面板加模式开关（撤销、对照现状、产物、试跑、按这个建），主按钮一屏只有一个。

全局模式四种：编辑（默认）、对照现状（叠加 chip 并压暗未变节点）、试跑（按顺序点亮自动节点）、汇报（隐藏组件库和属性面板）。模式互斥，切换不改位置只改标注。

07流程画布规格

7.1 布局

尺寸基准 1920×1080：侧栏 240，组件库 200，属性面板 292，画布内容区 1220×1024，可缩放 50% 到 160%。泳道分界 y=440 与 y=720，AI 在上，人在中，数据与系统在下。

对象字段说明

7.7 空状态、边界与错误

  • 没有空白画布。新建流程一律从一句话或模板生成草稿（原则 7）；真要空白，画布中央给三个动作：从一句话开始、选模板、拖组件。
  • 不兼容连线：拖到目标时线变红，松手不连，提示原因，例如「决定不能直接进数据系统」。
  • 删除不可逆前的人定节点：二次确认，并说明这是 PromptDog 的人工确认点规则。
  • 无人回复时：任何卡片与确认都有默认路径；试跑与构建不因缺口停下，缺口进未达标清单。
  • 子图内的空状态：新打包的狗至少有两个环节；钻进去看到与顶层一致的泳道。

10文案与语气

  • 说人话，结果先行。判级算式、策略名、信号打分默认收起，用户追问才展开。
  • 卡片是纠错窗口。所有确认类文案写成「我按 A 做了，不符再改」，不写「请确认」。
  • 按钮是动词，说清会发生什么：按这个建、应用建议、打包成工作狗、返回上一层。
  • 提示解释后果而不是操作：「X 标为要自动化：还缺一个组件来做它」。
  • 标记的名字固定：卡点、缺口、待打通；线的名字固定：顺序、数据、待打通、回填、退回。不发明同义词。
  • 示例数据一律标「示例」；真实事实缺失时用可见占位，如【待填】，不编造。

14待拍板

遇到这些不要替产品负责人决定
  1. 楔子场景与运行模型是否按 §2 的建议定下来。
  2. 部门泳道模式默认开还是按需开。建议按需，默认仍是按谁来做。
  3. 「按这个建」之后是进 03 资产包交付，还是直接入犬舍并回到画布。建议进 03 再入犬舍，交付物要让人看见。
  4. 组件版本策略：改一处全局同步是否需要审批。建议第一版不设审批，回归测试当门槛。
  5. 画布上的改动何时持久化：每次动作自动保存，还是显式保存。建议自动保存加版本历史。
