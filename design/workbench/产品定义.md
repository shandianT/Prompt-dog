# PromptDog 工作台 · 产品定义 v0.1（2026-09-08）

> 一页纸。定方向，不定细节；细节在 `SPEC.md`（怎么做）与 `stories.json`（按什么顺序做）。带 ★ 的是已建议的默认决定，带 H 的是未验证假设，改哪条说编号。

## 一句话

把公司的流程画成一张能拖、能拼、能看出卡点的地图，再把地图上的 AI 段打包成能上岗的工作狗。画布是中心，聊天窗口不是。

## 用户

| 角色 | 要什么 | 成功的样子 |
|---|---|---|
| 流程负责人 / 老板 | 30 秒看懂：哪些自动、人在哪、卡在哪、缺什么、打通什么；拍板改不改 | 不用别人解释就能指着图说「先打通招标平台」 |
| 搭建者（PM / 售前主管 / IT） | 把现状画出来，把 AI 塞进去，配组件，打通系统 | 一小时内从一句话到一张可建的目标流程 |
| 执行者（商务 / 售前） | 每天让工作狗跑起来，出问题知道退回哪一步 | 一条启动指令跑到交付，只在人审人定处停 |

## 两个已建议的决定

- **楔子场景 ★ 投标流程。** 跨销售、商务、售前、财务、领导五个角色，卡点真实，犬舍已有标书撰写狗。合同审查排第二。
- **运行模型 ★ 工作台是壳，引擎是用户自己的 Claude Code / Codex。** 画布产出资产包 + 启动指令 + `验收清单.json`，不自带执行；托管执行放以后。

## 五个核心场景

1. 一句话造工作狗（首页 → 确认卡 → 交付 → 入犬舍）
2. 画流程找卡点（材料反推现状图，标卡点 / 缺口 / 待打通，得重构建议）
3. 打通与补齐（系统节点定打通方式，缺口配组件，应用建议看目标态）
4. 工作狗上岗（一条指令跑到交付，人审人定处暂停，止损时给卡点报告）
5. 复盘回流（运行数据回到画布节点，改版跑回归）

## 非目标（第一版不做）

登录、计费、权限；托管执行与调度；视觉重塑；移动端；多人实时协作。

## 假设与验证

| 编号 | 假设 | 怎么验 | 验不过怎么办 |
|---|---|---|---|
| H1 | 老板能从泳道图 30 秒答出五问 | 3 个没看过的人看汇报模式，30 秒作答，4 问以上对 | 收窄标记种类，五问改三问 |
| H2 | 用户手里有能反推现状的材料（流程文档、聊天记录、表格） | 两家公司共创：收材料，看能否画出 80% 节点 | 改为「行业模板先行 + 访谈式选择题」 |
| H3 | 「壳 + 用户自己的引擎」被接受，不要求托管执行 | 共创时问「你愿意在自己的 Claude Code 里跑吗」 | 第二里程碑加托管 |
| H4 | 投标流程的卡点跨公司相似，模板可复用 | 两家公司的卡点重合 ≥ 60% | 楔子换成合同审查 |
| H5 | 组件资产化有价值：被两条以上流程复用的组件 ≥ 30% | 示例流程与第二条流程共用组件占比 | 打包功能降级为「另存为模板」 |

## 里程碑

| 阶段 | 做什么 | 出口 |
|---|---|---|
| 第 0 步 · 定方向 | 拍板两个决定；找两家公司在画布上共创投标流程 | 两条决定、一份访谈记录、修正后的示例数据 |
| 迭代 A · 读懂与默认值 | 一句话生成画布草稿、汇报模式、部门泳道、快捷键与整理 | 五问 30 秒达标 |
| 迭代 B · 组件资产化 | 打包真正入犬舍并生成资产包目录、组件详情、端口类型校验 | 打包后的狗能拖进另一条流程 |
| 迭代 C · 现状与运行态 | 材料反推现状、运行数据回流、契约闭合、人定节点保护 | 复盘数据出现在画布上 |

## 成功指标

五问 30 秒（4/5）· 一句话到草稿 60 秒 · 草稿到「按这个建」人工改动 ≤ 8 次 · 加一个连好线的节点 ≤ 2 个动作 · 投标示例卡点 2 → 0 · 不点任何确认也能跑完试跑与构建。

## 待拍板

1. 楔子与运行模型是否按上面定
2. 部门泳道默认开还是按需（建议按需）
3. 「按这个建」之后进交付页再入犬舍，还是直接入犬舍（建议进交付页，交付物要让人看见）
4. 组件改一处全局同步是否需要审批（建议不设审批，回归测试当门槛）
5. 画布改动自动保存加版本历史，还是显式保存（建议自动保存）
6. 前端技术栈：React + TypeScript + Vite，画布用 React Flow 还是自研（`stories.json` 第一条故事里做取舍）
