# 逐步评审：每个功能每一步——合理 / 缺少 / 没用 v0.1（2026-09-08）

> 这份是画每一步之前做的判断，也是画完之后的对账单。每个功能按用户走的顺序列出每一步，每步三栏：**合理**（为什么保留）、**缺少**（要加什么，加在哪）、**没用**（删什么，为什么）。最右一栏「决定」已经落到画布上：屏号对应设计画布「每个功能每一步」页的画板标题。示例数据均为演示值。
>
> 判断依据只有三条：① 这一步能不能不问就先做出来；② 用户在这一步只需要说编号或点一下；③ 停下来的地方是不是不可逆动作前。违反其一就是「缺少」或「没用」。

## 屏号约定

- 两位数是功能屏，小数点后是同一屏的**状态**：`05.3` = 上岗屏停在人工确认点。
- 新增的功能屏从 13 起编：`13` 诊断（贴提示词）、`14` 组件库列表。
- `07` 流程画布是可交互画板（1920 × 1080），它的五个静态状态 `07.0 / 07.2–07.5` 单独画成 1440 × 900，便于逐步看；`07.1 生成中` 与 `01.3` 是同一屏。

对账结果：

1. **无死角**：每一屏都有至少一个出口；07.0 空态与 14 组件库补上后，侧栏每一项都有落点。
2. **停机点仍是三个**：① 按这个建（07.3 / 11.x）② 人工确认点（05.3）③ 改版不改版（10.2）。13 诊断线没有停机点——符合「零提问诊断」。
3. **一个数字只有一个来源**：`验收清单.json` → 04 状态、05.2 计数、07.5 运行态、09 达标；flow JSON → 07 / 08 / 03.1 未达标链接 / 11 右栏 / 14 「复用于」；版本号 → 09 / 14 / 04。
4. **改名**：画布「试跑」→「运行态」；「会话内试跑」仍指 03 构建流水线里的自检（SKILL 术语），两者不再混。
