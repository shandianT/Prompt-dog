# 开源选型 v0.1（2026-09-08）

> 原则：**已有的功能都用现成开源项目，自己只写差异化的那部分。** 每条给准确许可证、复用方式（fork / 依赖 / 只借鉴）、以及为什么。PromptDog 本体是 MIT，所以许可证兼容性是硬约束。

## 一句话结论

不 fork 任何工作流产品。**画布依赖 React Flow**（Dify、Langflow、Flowise 三家的画布底座都是它），执行引擎不做（是用户自己的 Claude Code），我们只自研两样别人没做过的：**泳道语义**与**对照现状**。

## 决定表

| 能力 | 怎么解决 | 项目与许可证 | 理由 |
|---|---|---|---|
| 流程画布 | **依赖** | `@xyflow/react` v12 · MIT | 缩放、框选、撤销、只读、类型化端口与连线校验、子图与打包全部原生 |
| 自动布局 | **依赖**（可选） | `elkjs` · EPL-2.0 | 文件级弱 copyleft，作为未修改依赖不传染 MIT 代码；我们的泳道布局是按 y 分带的简单规则，第一版可以不用 |
| 图导出 PNG / PDF | **依赖** | `html-to-image@1.11.11` + `jsPDF` · MIT | 版本必须锁 1.11.11，之后版本导出有 bug |
| 文本档图（环境封顶第二档） | **依赖** | `mermaid` · MIT | `process-rebuild.md` 三档表的中间档 |
| 执行引擎 | **不做** | — | 运行模型已定：工作台是壳，引擎是用户自己的 Claude Code / Codex |
| 托管执行（用户想要时） | **导出互操作** | 导出 Dify DSL（YAML） | 见下方「与 Dify 的关系」 |
| 泳道（按角色 / 按部门） | **自研** | — | React Flow 官方不提供，社区实现都很小；我们原型已用「静态分带背景 + 节点按 y 区间归带」跑通 |
| 对照现状叠加 | **自研** | — | 没有任何开源项目做过 |

## 画布：为什么不 fork，依赖谁

三家 AI 工作流产品的画布底层是同一个库：

| 项目 | 画布依赖 |
|---|---|
| Dify | `reactflow` + `elkjs` |
| Langflow | `@xyflow/react` ^12 + `reactflow` ^11 + `elkjs` |
| Flowise | `reactflow` ^11 |

所以 fork 它们等于 fork「React Flow 的一层业务封装 + 一个我们不需要的执行引擎 + LLM 网关 + 向量库集成」。直接依赖 React Flow，等于站在它们同一个地基上，而不背它们的房子。

许可证核查（这是出局的主要原因，不是功能）：

| 项目 | 许可证 | 结论 |
|---|---|---|
| Dify | **修改版 Apache 2.0**：未经书面授权不得用其源码运营多租户环境；**用其前端必须保留 LOGO 与版权信息**；贡献者须同意协议可被改严 | ❌ 不能 fork 进 MIT 仓库再换品牌 |
| n8n | **Sustainable Use License 1.0**（源码可见，非开源）：仅限自用内部业务；分发须免费且非商业 | ❌ 直接出局 |
| Langflow | 纯 MIT | ✅ 唯一敢 fork 的，但仍带 Python 执行栈 |
| Flowise | Apache 2.0 + `enterprise/` 目录商业例外 | ⚠️ 主体可用，须剔除 enterprise |
| **React Flow / xyflow** | **纯 MIT**，许可证内无水印条款 | ✅ **选它** |
| Rete.js | 纯 MIT | 备选，生态与示例远少于 React Flow |
| ComfyUI | GPL-3.0 强 copyleft | ❌ 会污染 MIT |
| bpmn-js | MIT + **水印条款写进许可证**：bpmn.io 水印不得移除或遮挡 | ⚠️ 泳道是它的一等公民，但要永久露出他家水印，且我们的 kind / role / flag 塞不进 BPMN 标准 |
| pm4py | AGPL-3.0 | ❌ |

React Flow 的 Pro 不是功能墙：核心库全部 MIT，没有 pro-only 功能，Pro 卖的是高级示例、优先 issue 与支持，他们连 Pro Platform 本身都开源成 MIT。水印在代码里只是 `proOptions.hideAttribution` 一个开关，许可证不强制——与 bpmn-js 把水印写进许可证性质不同。建议照常订阅或保留署名，这是他们维持维护的方式。

## 与 Dify 的关系：上下游，不是竞品

**Dify 的图是执行图，我们的图是诊断图。** 我们图上有三样它没有的：卡点 / 缺口 / 待打通标记、`was` / `target`（对照现状）、泳道的人机边界语义。它图上有我们不做的：执行。

Dify 1.13 起有 **Human Input 节点**：工作流暂停等人、人可审阅并修改变量、自定义动作按钮（通过 / 驳回 / 上报）决定后续分支、引擎持久化暂停态、支持超时默认路由。这与我们的「人审 / 人定 + 人工确认点只在不可逆动作前 + 无人回复走 ★ 默认路径」高度同构——趋同演化，佐证方向没错。

所以互操作方向是**单向导出**：目标态流程图 → Dify DSL（YAML），丢掉诊断信息、保留可执行骨架，给想要托管执行的用户一条路，我们不写引擎。映射：

| 我们的 | Dify DSL |
|---|---|
| `node.id` / `x,y` / `name` | `id` / `position.{x,y}` / `data.title` |
| `kind=human, role=review/decide` | `data.type = human-input`（动作按钮 = 通过 / 退回 / 先看） |
| `kind=dog` | `agent` 节点或子 workflow |
| `kind=skill` | `llm` / `tool` / `code` |
| `kind=data` | `tool` / `http-request` / `knowledge-retrieval` |
| `kind=know` | 无对应，并入 llm 节点的提示词 |
| `edge.from/to` | `source` / `target` |
| `edge.kind=back` | human-input 的动作分支 |
| `edge.kind=data` | Dify 用变量选择器传数据，不画数据线 |
| `flag` / `was` / `target` / 泳道 | **无对应——这是我们的差异化** |

Dify 1.16 已有 AI 工作流生成器（一句话生成可导入的 DSL），社区也已有 Claude Code 技能生成 Dify DSL。所以「一句话造工作流」这件事已是行业标配，**我们的价值不在这里**，在于：诊断现有流程、产出跑在用户自己环境里的资产包、以及方法论规则本身。

## 评测：用 promptfoo 补上没有跑器的缺口

`evals/evals.json` 从没被执行过。选 **promptfoo（MIT）**，它是唯一同时满足四条的：MIT、声明式文件定义用例、断言可写自然语言、能驱动 CLI 型 agent。

| 候选 | 许可证 | 结论 |
|---|---|---|
| **promptfoo** | MIT | ✅ 选它。评测 100% 本地跑，提示词不离开机器；`llm-rubric` / `g-eval` 断言直接吃自然语言判据；`exec:` provider 可直调任意 CLI；官方有《Evaluate Coding Agents》指南覆盖 Claude Agent SDK 与 Codex，支持 `working_dir` 工作区；CI 有官方 GitHub Action，可出 JUnit XML 卡门禁，不需要账号 |
| DeepEval | Apache-2.0 | 备选。G-Eval 支持自然语言标准，但用例是 Python 代码而非声明式文件 |
| Ragas | Apache-2.0 | ✗ 形态错位，RAG 指标为主，agent / prompt evals 仍是 Coming Soon |
| OpenAI Evals | MIT | ✗ 近乎停更；OpenAI 托管 Evals 将于 2026-11-30 关停，**官方迁移路径直接指向 promptfoo** |
| Inspect AI (UK AISI) | MIT | ✗ 过重，纯 Python DSL，为模型能力基准设计而非提示词规则 |
| autoevals (Braintrust) | MIT | 只是 judge 打分器库，无跑器无 CI 报告 |

落法：写一个 `evals/evals.json → promptfooconfig.yaml` 转换器。`prompt` 进 `vars`；`expected_output` 整段原样喂给 `llm-rubric`；`files` 映射成 `working_dir` 工作区；provider 用 `exec: claude -p …` 真实跑一遍 Claude Code；CI 用官方 Action 输出 JUnit XML。判据本来就是自然语言写的（「应判为 L3、应零提问直接交付、产物形态应是资产包」），不用改写用例。

## 观测：不引入任何平台

三条硬约束——跑在用户本地 CLI、无服务端、MIT 项目——把主流方案全部排除：

| 候选 | 许可证 | 为什么不用 |
|---|---|---|
| Langfuse | MIT，但 `ee/`、`web/src/ee/`、`worker/src/ee/` 三个目录走商业许可 | 自托管要 Postgres + ClickHouse + Redis + S3 四件套 |
| Phoenix (Arize) | **Elastic License 2.0**（非 OSI 开源，禁止作为托管服务提供） | 技术上能纯本地跑，但许可证不是开源；只能作为用户自选的查看器，不进我们依赖树 |
| Helicone | Apache-2.0 | 代理网关型，要改 baseURL，与「跑在用户自己的 Claude Code 里」结构冲突 |
| OpenLLMetry | Apache-2.0 | ○ 可选：作为 OTLP 导出，不绑任何云 |
| OTel GenAI semconv | Apache-2.0（纯规范，零运行时） | ★ 只借命名：`invoke_agent` / `execute_tool` / `gen_ai.*` |

结论：`验收清单.json` 与 `复盘/日志.md` 保持唯一事实来源，只把字段命名对齐 OTel GenAI 语义约定并在文档里锁定版本（该规范 2026-06 迁出主仓成独立项目，且全部条目仍是 Development 状态，agent 与 tool 部分改动最频繁，所以只对齐命名、不依赖其稳定性），再提供一个可选的 OTLP 导出。想看可视化的用户自己起 Phoenix 即可。

## 资产包：我们以为的差异化，其实是已有标准

**Agent Skills 已是开放标准**（`agentskills/agentskills`，Apache-2.0 代码 + CC-BY-4.0 文档，Anthropic 发起后捐出）：最小要求就是一个 `SKILL.md`（frontmatter 至少 `name` 与 `description`），可选 `scripts/` `references/` `assets/`。

对照本仓库：根目录是 `SKILL.md` + `references/` + `assets/`，frontmatter 是 `name` + `description`——**我们已经完全符合这个标准，不是自造格式**。犬舍每只狗也有合规的 `SKILL.md`，额外的 `prompts/` `templates/` `复盘/` 属于允许的自定义目录。

| 项目 | 许可证 | 关系 | 动作 |
|---|---|---|---|
| Agent Skills 规范 | Apache-2.0 / CC-BY-4.0 | **完全重合**，我们已经是 | 改口径：README 从「我们的资产包格式」改成「**符合 Agent Skills 开放标准的资产包**」，把兼容性当信任状 |
| AWS `agent-sop`（`.sop.md`） | Apache-2.0 | 格式上最直接的重合：Overview / Parameters / Steps（RFC2119 MUST-SHOULD-MAY）/ Troubleshooting，自带进度记录与断点续跑，且可转成 `SKILL.md` | 借鉴 RFC2119 的约束写法，不迁移 |
| Claude Code 插件市场 | — | `.claude-plugin/marketplace.json` 一个文件即可被 `/plugin install` 订阅 | **我们缺这个文件**，是分发上的最大漏洞 |
| AGENTS.md | 开放标准（已归 Linux Foundation Agentic AI Foundation） | 已用 | 继续 |
| MCP Registry | 开源 | 互补，分发的是 tool 不是 skill | 无视 |
| OpenAI AgentKit | 闭源，2026-11-30 下线 | 反向利好 | 无视 |

## 无人上岗：不换 `上岗.sh`，但要对齐官方能力

Claude Code 已内置 `/loop`（按间隔或 until 条件重复）、`/goal`（跨轮追终止条件）、`/batch`。这直接进了 `上岗.sh` 的地盘。

**结论是不换**：`上岗.sh` 只有 20 行、零依赖，驱动的是 `验收清单.json` 里的**业务验收项**（废标项逐条打钩、引用附页码），不是测试退出码；换成 OpenHands 这类等于给非技术用户加一个 Docker 依赖。但要做两件事：停机标记语义对齐 `/goal`；文档里写明 Claude Code 用户可以用 `/loop until:` 零脚本替代 `上岗.sh`。ralph 已借完（上游 2026-02 后停更），aider 与 Goose Recipes 的参数化可继续借鉴。

## 竞品：完整链条在开源里是空的

| 项目 | 许可证 | 做了什么 | 关系 |
|---|---|---|---|
| ProMoAI | **AGPL-3.0** | 自然语言或事件日志 → BPMN / PNML + 分析报告 | 只画图不生成 agent；许可证不可被 MIT 吸收，**只借思路不碰代码** |
| BESSER-PEARL/agentic-bpmn | 开源 | BPMN 扩展：**agentic lane + trust score + agentic gateway** | 正是「人 / AI 泳道 + 该不该交给 AI」的记号法，**直接借记号法** |
| BaseFrame（YC W26） | **闭源** | 连邮件、会议、文档，挖出重复工作流并告诉你哪些值得自动化 | **诊断段的正面竞品**，盯住 |
| GitHub Spec Kit | MIT | 规格 → 执行产物，支持 30+ agent | 只做软件不做部门流程，借鉴 |
| Dify / n8n / Coze | 见上 | 编排执行 | 确认非竞品 |

**关键判断**：现有方案全部依赖**事件日志**才能发现流程，而中小企业根本没有可挖的日志。PromptDog 的「对话式采集 + 带 ★ 的选择题澄清」正好绕开这个前提——这是护城河所在。

## 护城河要挪位

「资产包」已被 Agent Skills 标准和 AWS agent-sop 双重覆盖，**继续当卖点讲会被识破**。真正无人竞争的是两件：

1. **无事件日志的流程诊断**——BaseFrame 要连你的邮箱，我们只要你说话。
2. **说不清需求的人也能用**——Spec Kit 假设你写得出 spec，我们假设你写不出。

三步动作，按收益排序：

| # | 动作 | 成本 | 收益 |
|---|---|---|---|
| 1 | 补 `.claude-plugin/marketplace.json`，让犬舍能 `/plugin install` | 约一天，需先定 SKILL.md 的目录布局 | 接入 25+ 客户端的安装路径 |
| 2 | README 口径改成「符合 Agent Skills 开放标准」 | 半小时 | 把兼容性当信任状，而不是把重合当差异化 |
| 3 | 借 agentic-bpmn 的 agentic lane 与 trust score 记号法强化泳道图 | 一周 | 把流程重构做成抄不走的那一块 |
