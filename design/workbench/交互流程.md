# 交互流程：用户怎么用，每一步 v0.1（2026-09-08）

> `使用逻辑.md` 说的是「第一周做哪五件事」，这份说的是**每一步的界面行为**：在哪屏、你看到什么、你做什么、系统做什么、产物落在哪、停在哪、不回复会怎样、出错怎么办。写给做前端的人和写技能规则的人；产品负责人只需要看主线表和末尾的停机总表。

## 三条贯穿每一步的规则

1. **先做出来再纠错。** 每一步系统都先给出完整产物，不先问问题。只有会改变架构的事才成题，其余转 H 假设写在产物里。
2. **纠错只有一种语法：说编号。** 节点号改图，H 号改假设，环节号改狗，故事号改设计。不需要学别的操作。
3. **只在不可逆动作前停。** 发送、发布、提交、付款、签署之前会停下来等你，其余分叉都有 ★ 默认路径，不回复也会走完。

---

## 第 0 步 · 安装（一次性，5 分钟）

| | |
|---|---|
| 在哪 | 你自己的 Claude Code / Codex 工作区，不在工作台里 |
| 你做 | 把 `Prompt-dog/` 整个文件夹放进项目根目录；在根目录 `AGENTS.md` 加一段路由（原文见 `QUICKSTART.md` 第二节） |
| 系统做 | 下次会话自动读到，无需重启或安装依赖 |
| 怎么算成功 | 说「帮我写一个把会议纪要总结成三条要点的提示词」，它不反问，直接给完整提示词 |
| 出错怎么办 | 它连续反问 → 回「按技能流程来，出选择题」；它每步等确认 → 回「直接做，按推荐」 |

没有工作台也能全程在对话里走完。工作台只是把图和进度放到眼前。

## 主线

### 1 · 第一次打开

| | |
|---|---|
| 屏幕 | 00 首次引导 |
| 你看到 | 五步时间线，当前步高亮；右栏「你需要准备的」四项、「什么时候用哪个入口」四行、常见误区四条 |
| 你做 | 点「开始这一步」，或点右上角「跳过引导」 |
| 系统做 | 记住进度；完成第 1 步后引导收起为顶栏一个进度 chip |
| 停在哪 | 不停，随时可跳过 |
| 不回复 | 引导不阻塞，直接进 01 首页也能用 |

### 2 · 说一段流程，把材料丢进来

| | |
|---|---|
| 屏幕 | 01 首页 |
| 你看到 | 一个大输入框；四个入口 chip（一句话 / 贴提示词 / 一段流程 / 产品想法）说明它会自动识别；「贴材料」按钮是琥珀描边的，比「直接做」更显眼；右栏三张预览卡说明会先做出什么 |
| 你做 | 说一段流程（谁做什么、什么顺序、卡在哪、用哪些系统），顺手把流程文档、聊天记录、表格拖进来。说不清也可以，它会给候选让你挑 |
| 系统做 | 判入口（这里命中「流程重构」，不判级）；**有材料就从材料反推现状，每个节点记来源；没材料按行业候选库出草稿并写 H 假设** |
| 产物 | 流程图 JSON |
| 停在哪 | 不停，直接出图 |
| 不回复 | 不适用，这一步必须你先说话 |
| 出错怎么办 | 入口判错（比如你要图它给了资产包）→ 回一句「我要的是图」，它改路由重出，不重问 |

### 3 · 读图：三十秒答完五问

| | |
|---|---|
| 屏幕 | 07 流程画布（要给老板看就切 08 汇报模式） |
| 你看到 | 三条泳道（AI 自动 / 人 · 人审人定 / 数据与系统）；顶栏五个数字：自动 N · 人 N · 卡点 N · 缺口 N · 待打通 N；节点上三种标记：卡点红、缺口琥珀、待打通蓝；右栏诊断清单把三种标记逐条展开，每条写「怎么解」 |
| 你做 | 只是看。目标是三十秒回答：哪些自动、人在哪、卡在哪、缺什么、要打通什么 |
| 系统做 | 无 |
| 怎么算成功 | 找三个没看过的人，三十秒内答对四问 |
| 出错怎么办 | 图和实际不符 → 进第 4 步纠错，不用重来 |

### 4 · 纠错：说编号，或直接拖

| | |
|---|---|
| 屏幕 | 07 流程画布 |
| 你做 | 四种改法：说节点编号改内容（「n9 报价其实要三天」）；把人的步骤**拖进 AI 泳道** = 这步要自动化；把 AI 节点**拖进人泳道** = 改成人审；点诊断清单里的「应用」把某条建议变成目标态 |
| 系统做 | 拖过泳道边界会改「谁来做」并提示；人的步骤进 AI 泳道会自动标缺口（还缺一个组件来做它）；**不可逆动作前的人定节点受保护，不能改成自动**；每一步可撤销 |
| 产物 | 更新后的流程图 JSON |
| 停在哪 | 不停 |
| 不回复 | 不改也行，草稿本身就是可用的目标态 |

### 5 · 按这个建

| | |
|---|---|
| 屏幕 | 07 顶栏主按钮 → 02 |
| 你看到 | 右栏先出「构建预览」：会建哪几个环节、要哪些工具、人工确认点在哪、交付前必须解决什么 |
| 你做 | 点「按这个建」；或直接说「先建标书撰写」 |
| 系统做 | 取打包建议里的第一只狗转主循环判级；缺口和卡点没解决也能建，会写进未达标清单 |
| 停在哪 | 这是一次拍板，但**无人时取楔子 ★ 那只**，不会卡住 |

### 6 · 确认卡（只在架构级不确定时出现）

| | |
|---|---|
| 屏幕 | 02 |
| 你看到 | 最多两题，都是会改变架构的事（在哪运行、错误代价）；其余已转成 H 假设列成一排 chip；右栏产物**同时在生成**，不等你回答；主按钮写着「不用回复 · 已按 ★ 进行」 |
| 你做 | 什么都不做也行。要改就回「1C」或「H2 不对，实际是…」 |
| 系统做 | 未答项一律取 ★；回复后只重出受影响的部分，不重来 |
| 停在哪 | 不停 |
| 不回复 | 按 ★ 全部生效，照常交付 |

### 7 · 交付与入犬舍

| | |
|---|---|
| 屏幕 | 03 资产包交付 → 04 犬舍 |
| 你看到 | 构建流水线逐项打钩；右栏目录树（含 `验收清单.json` 与 `上岗.sh`）；四道保险；未达标清单，每条链到画布上对应的缺口节点；H 假设每条带「改」；三个出口：下载 / 入犬舍 / 画布中查看 |
| 你做 | 点「入犬舍」。想改就说环节号或 H 号 |
| 系统做 | 资产包落盘；在流程画布上占一个节点；主控文件写进「服务流程与节点号」，复盘时数据才能回到图上 |
| 产物 | 资产包文件夹 |
| 停在哪 | 不停，交付就是完成 |

### 8 · 上岗一次

| | |
|---|---|
| 屏幕 | 05 工作狗上岗 |
| 你做 | 把资产包放进工作区，按 `启动指令.md` 跑一份**真实材料**；或运行 `上岗.sh`（Claude Code 用户也可以用 `/loop until:`，零脚本） |
| 系统做 | 一轮一个环节，每轮新开上下文；每轮把验收项逐条打钩写回 `验收清单.json`，并追加一条 `复盘/日志.md` |
| 你看到 | 环节进度，每环节显示验收计数；顶栏显示当前轮次与停机状态 |
| 产物 | 交付物落盘 `输出/`；日志开始累积 |
| 停在哪 | 只在不可逆动作前 |
| 不回复 | 停在待确认那一步等你，不会自动发送 |

### 9 · 人工确认点

| | |
|---|---|
| 屏幕 | 05，停机状态 chip 显示「待确认」 |
| 你看到 | 一张卡：为什么停（对外发送前）、右侧已生成的交付物、三个选项：通过并落盘 / 退回到某个环节 / 先看报告暂不发送 |
| 你做 | 选一个，或直接说「R-002 改成…」当场改内容 |
| 系统做 | 通过 → 落盘并结束；退回 → 重跑那一环节及其下游；暂不 → 保持停机 |
| 不回复 | **一直停着**。这是全流程唯一不会自己往前走的地方 |

### 10 · 复盘

| | |
|---|---|
| 屏幕 | 10 复盘与回归 |
| 你做 | 说「复盘」 |
| 你看到 | 四指标带上期对比；历史样本的回归对照；发布门槛清单（几项通过、哪几项没过）；提示词修改建议与回填素材库；右栏是已达触发条件的回流建议与已知规律 |
| 系统做 | 读日志与卡点报告，不重跑环节；本次教训追加进日志，跨项目规律写进日志顶部「已知规律」 |
| 停在哪 | 「改版 / 不改版」；**回归没过就不许发布** |
| 不回复 | 日志照常累积，不改版 |

### 11 · 回到图上，建第二只

| | |
|---|---|
| 屏幕 | 07（切「对照现状」）或 08 汇报模式 |
| 你看到 | 每个变过的节点标「原：人做 / 手工搬 / 新增」，未变的压暗；卡点数从 2 变 0 |
| 你做 | 看变化，决定下一只建谁 |
| 系统做 | 无 |
| 停在哪 | 「下一只建谁」，回到第 5 步 |

## 分支与异常

| 情况 | 会发生什么 | 你要做什么 |
|---|---|---|
| 入口判错 | 你要图它给了资产包，或反过来 | 回一句「我要的是图」/「直接建」，它改路由重出，不重问 |
| 材料不足 | 现状图按行业惯例出草稿，每个推断处标 H | 不用先整理材料。第二次投标时再补，缺的它会标成缺口 |
| 中途改主意 | 你加了「再自动发个邮件」这类实质变化 | 它重算复杂度，变级会宣告并换产物形态，不变级就地改 |
| 上岗止损 | 某一轮精调后验收打钩数没有增加 | 它**同时**给三样：已达标部分、未达标清单、卡点报告。不会空转，也不会只上报不交付 |
| 回归不达标 | 改版后历史样本跑不过 | 发布门槛拦住，先改提示词再重跑，不许发布 |
| 全程无人 | 定时、批量、被脚本调用 | 不出任何卡片，全取 ★，一次交付；只在不可逆动作前停 |
| 你说「直接做」 | 任何时候 | 卡片全部折叠进 H 假设，一次交付 |

## 停机总表：全流程只有三个地方会停

| 停在哪 | 什么时候 | 不回复会怎样 |
|---|---|---|
| 「按这个建」 | 第 5 步，决定先建哪只狗 | 无人时取楔子 ★ 那只，继续 |
| 人工确认点 | 第 9 步，对外发送 / 提交 / 付款前 | **一直停着**，不会自动执行 |
| 「改版 / 不改版」 | 第 10 步，复盘之后 | 不改版，日志照常累积 |

其余每一处分叉都有 ★ 默认路径。这是「卡片是纠错窗口，不是审批关卡」在界面上的完整含义。
