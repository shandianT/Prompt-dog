# PromptDog 工作台

流程画布 MVP 的前端工程。**已完成 S01 骨架与数据契约、S02 FlowNode 组件、S03 画布与泳道、S04 五种连线与标签、S05 选中 / 移动 / 框选 / 撤销、S06 属性面板、S07 拖线与契约校验、S08 快速添加、S09 泳道语义与角色切换、S10 对照现状 / 应用建议 / 运行态**；打包与钻取从 S11 起。

## 这个工程是干什么的

PromptDog 有两层：

| 层 | 是什么 | 状态 |
|---|---|---|
| **方法** | `../SKILL.md` + `../references/`：说一段流程，它用文字给你泳道表、卡点、打包建议；说「先建标书撰写」，它给你资产包 | **已完成，今天就能用，不依赖任何代码** |
| **产品** | 这个工程：把「读文字版的诊断」变成「在屏幕上看一张图、在图上拖一下」 | 建设中，按 `../design/workbench/stories.json` 一条一条来 |

为什么要建产品层——文字版的流程诊断只有会用 Claude Code 的人能用；一张标了卡点的泳道图，任何业务负责人 30 秒能读懂、能拿给老板看、能把一步拖进 AI 泳道说「这个交给 AI」。`../design/workbench/开源选型.md` 里写明了：一句话生成工作流 Dify / n8n 都有，我们唯一别人没做的两样——**泳道语义**和**对照现状**——只存在于画布上。

如果你只是想自己用 PromptDog，方法层已经够了。这个工程是为了让不打开 Claude Code 的人也能用，以及让它成为一个能展示、能给别人试的产品。

前三条故事看着不像产品，这是正常的：S01 定「一张流程图在文件里长什么样」（三处看同一份文件，这份错了后面全错），S02 定「图上每个方块长什么样」（方块读不懂，图就读不懂），S03 才把方块放到泳道上——从这里开始长得像设计画布里的 07 屏。

## 数据契约

**唯一来源是 [`../design/workbench/flow.schema.json`](../design/workbench/flow.schema.json)**，这里不拷贝副本：
技能产出它、画布渲染它、复盘回流改它，三处必须看同一个文件。`src/flow/schema.ts` 直接 import 它，
`vite.config.ts` 为此放行了仓库根目录。

```
src/flow/
├── types.ts      TS 类型，与 schema 一一对应；枚举写成 as const 数组，供漂移检查比对
├── schema.ts     import 仓库里的 schema，导出 x-compat 规则原文
├── validate.ts   ajv 校验 + 可读的中文错误 + 枚举漂移检查
├── compat.ts     x-compat 四条规则的实现 + 引用完整性
├── connect.ts    拖线的判定：什么能连（只拦连自己 / 已连过 / 决定进数据节点）、新线长什么样
├── palette.ts    组件库的一项怎么变成节点：默认值、子图前缀、按种类归入泳道
├── laneRule.ts   跨泳道的语义（人进 AI = 变技能标缺口；AI 进人 = 改人审）、撞边提示、角色循环
├── target.ts     「应用建议」：把节点切到 target，记原：人做 / 原：手工搬，待打通线降级
├── run.ts        运行态：读 验收清单.json，算每个节点的徽章与汇总
├── lanes.ts      画布几何与泳道分带（150×64 节点，y=440 / 720 分界）
└── stats.ts      五问数字与连线计数
```

四道检查，任一不过 `npm run check` 退出码 1：

1. **schema** — 字段、枚举、必填、`additionalProperties: false`
2. **枚举漂移** — `types.ts` 的枚举必须等于 schema 的枚举（编译器管不到，所以显式比）
3. **引用完整性** — 连线两端指向存在的节点、id 不重复（跨对象引用 schema 管不到）
4. **x-compat 四条规则** — 字段合法不等于组合合法，这四条查的是组合

`scripts/check-guards.ts` 用十个故意改坏的流程图证明这四道检查真的会报错，另有六条连线判定（什么能连、连出来是什么线）、五条泳道语义（跨过去意味着什么、撞边说什么）和五条应用建议 / 运行态（应用后长什么样、示例清单算出几个徽章）。

S05 的操作约定（SPEC §6.4）：拖节点 = 移动，选中的一起动；空白处拖 = 框选，相交即选中；Shift / Cmd / Ctrl + 点 = 加选；≥ 2 个选中出浮条。平移用按住空格拖、中键或右键拖，滚轮仍是缩放（S03 定的，等真人用过再议）。撤销栈 40 步（Cmd/Ctrl+Z 或顶栏「撤销」），一次拖动 = 一步，只回节点与连线不回选中；方向键微移 1px、Shift 10px；Delete / Backspace 删除选中。

S06 的属性面板（SPEC §6.5）：无选中显示诊断——三行数字与顶栏同一来源，chip 点了选中节点，每个带标记的节点一条建议；选一个节点显示分类型字段；选一条线显示产物 / 类型 / 关系 / 契约。所有改动走 `useFlowEditor` 的 updateNode / updateEdge，一次改动一步撤销，文本框失焦或回车才写回。契约不拦只提示：x-compat 里与当前对象有关的规则显示在面板里。两条会连锁：受保护的人定节点「谁来做」只能选人定；数据节点打通方式改成非人工时，它的待打通线自动降为数据线、待打通标记清掉。删除有三条路：面板按钮、Delete / Backspace、浮条。

S07 的拖线（SPEC §6.4）：从输出端口拖到另一个节点身上任何地方松手就连上；新线的种类与产物由 `connect.ts` 定——两端有数据节点是数据线，那个数据节点还在待打通就是待打通线，否则顺序线，产物 = 来源节点的输出类型。连不上的只有三种：连到自己、已经连过、决定类产物直接进数据节点（契约规则 1）；拖的过程中线就变红、原因跟着线，松手不连并在底部提示。每块卡片一直铺着一个看不见的目标 Handle，拖线中才接指针事件：React Flow 只在节点挂载时量 Handle 的位置，临时出现的 Handle 它认不出来。

S08 的快速添加（SPEC §6.4、§6.5）：端口拖到空白松手弹组件搜索，占位符写着「接在「X」之后…」，选中即新建并连上——两个动作加一个连好线的节点；双击空白弹同一个搜索；左栏组件库五组可拖入，幽灵节点跟着指针，画布上松手即建。新节点的默认值在 `palette.ts`：数据类默认待打通，人带角色，工作狗带子图；落点按种类归入对应泳道（数据 → 数据泳道、人 → 人泳道、其余 → AI）。组件库数据来自 `sample/组件库.json`，与流程示例一样从 `flow.py` 导出。

S09 的泳道语义（SPEC §6.6）：步骤节点可以在 AI 与人两条泳道之间拖，松手时按 `laneRule.ts` 改——人的步骤进 AI 泳道变技能、自动、标缺口、记「原：人做」（还缺一个组件来做它）；AI 节点进人泳道改人审，类型不变。规范里三条「弹回」改成挡在边界上：数据节点出不了数据泳道，步骤节点进不了数据泳道，不可逆动作前的人定节点进不了 AI 泳道；撞到边上会说一句为什么。位置和语义一次提交、一步撤销。点角色徽章循环 自动 → 人审 → 人定，受保护的不动；节点上右键出菜单：改谁来做、标记状态、删除 / 删除所选。「打开子流程」「打包」两行是 S11。

S10 的三个看图方式与「应用建议」：顶栏「对照现状」压暗没变过的节点，变过的出 chip（原：人做 / 原：手工搬 / 新增，按节点的 `was`），右栏切到对照汇总——五个数字前后对照（「前」= 加载时的示例）和按 was 分组的变化。「应用建议」在节点面板和诊断列表两处，把节点切到它的 `target`（`target.ts`）：人变组件记原：人做并归到 AI 泳道，数据节点打通方式从人工变接口记原：手工搬、待打通线降为数据线，一步撤销。顶栏「运行态」不是试跑：读 `sample/验收清单.json`（结构按 `references/run-loop.md`，多三个可选字段 `环节[].节点`、`复用[]`、`节点状态[]`），每个节点显示打钩数徽章，当前环节外圈光晕，右栏是运行态汇总。画布不执行任何东西。

状态在 `useFlowEditor`：flow（契约）是真相，React Flow 的 nodes / edges 是它的视图态；拖动过程中只有视图在变，松手才写回整数坐标并推快照。快捷键挂在 window 的捕获阶段，因为 React Flow 自带的方向键与 Esc 处理要么不进撤销栈、要么会把刚清空的焦点节点重新选上。

S04 的连线：路径**逐字移植**自原型 `flow.py` 的 `edgePath`，两边算出来的线必须一样；标签用 HTML（`EdgeLabelRenderer`）而不是 SVG `<text>`——要省略号、要用 token，只有 HTML 能做；默认只显示非顺序线与决定类的标签，顶栏「产物」开关显示全部。首帧取景到**整幅画布**而不是节点外框：回填线贴着画布右边和底边绕，按节点外框取景会把它裁掉。建到这里发现原型两处问题（紧挨的节点之间标签被盖住、泳道提示语被回填线划过），已同步改回 `flow.py`——建产品是对设计最严的评审。

没有引 Storybook：变体页就是它的替代品——一个组件家族一页，每个状态一格，
`npm run dev` 里点开就能看，`npm run check:ui` 在无头浏览器里逐条断言。
样式写在同名 `.css` 里而不是 Tailwind 类名：节点的状态组合（边框 × 虚实 × 角标 × 光晕）
用类名表达会长到读不动，而且颜色必须走 `tokens.css` 的变量，不能在组件里写死十六进制。

`check:ui` 跑在 **devicePixelRatio = 2** 下。SPEC §6.3 要求人节点 1.5px 边框，
而 DPR 1 时 Chrome 会把 1.5px 的「用值」舍成 1px，在那个密度下断言 1.5px 会假报错。
