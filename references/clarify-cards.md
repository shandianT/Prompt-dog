# 澄清卡片手册

出任何确认卡片前读本文件。目标：让用户最少回一句「都按推荐」即可放行。

## 卡片模板

```markdown
## 确认卡片（第 1/2 轮）
以下按我的理解预填了推荐项（★）。你可以：
回复「都按推荐」一键通过 / 用简写如「1A 2C 3默认」/ 直接一句话修正任何选项。

**Q1 <方向级问题>**
- A. <选项> ★推荐：<一句理由>
- B. <选项>
- C. <选项>
- D. 其他（一句话说明）

**Q2 <问题>**（可多选，如 2AC）
- A. <选项> ★  B. <选项>  C. <选项> ★  D. 其他
（★A+C 推荐：<一句合并理由>）
```

硬规则：

- 每题 2–4 个实质候选，外加一个「其他」逃生口——候选是猜测，猜错时用户不该被迫硬选。
- 每个 ★推荐必附一句理由，让用户能判断推荐是否适用于自己，而非盲从。
- 多选题显式标注「可多选」。
- 一轮只出一张卡片；题数与轮数预算见 SKILL.md。
- 第 2 轮题目必须由第 1 轮答案派生（选了「给高管看」才问「一页摘要还是完整报告」）；答案不影响后续设计的题不许问。

## 运行环境题（L3/L4 首轮必含）

编排方案必须按目标环境裁剪，否则工具清单会列出根本不存在的能力：

```markdown
**Q_ 这套流程将在哪里运行？**
- A. 普通 AI 对话窗口（无工具，每步手动执行）
- B. 带工具的 Agent 环境（可联网搜索、读写文件）★推荐：<按用户描述给理由>
- C. API / 代码编排（可定时触发、可并行）
- D. 其他 / 不确定（一句话说明）
```

示例中 ★ 的位置只是占位——按用户陈述把 ★ 预填到最匹配的选项上（说了「每月自动」，★ 就该落在 C）。
A 环境：不得设计依赖搜索/定时的环节，改为「用户粘贴材料」+ 手动逐段执行说明。
D 不确定：按 A 的最保守假设设计，并在假设清单标注升级路径。

## 选项三源法（候选从哪来）

1. **任务陈述推断**：从用户原话提取实体与暗示（「每周」→ 定时触发与周环比；「发给客户」→ 错误代价高）。
2. **行业模式库**：查下方候选库。行业 know-how 永远由你提案、用户修正——用户说「做电商客服质检」，直接列出常见质检维度让他勾选，绝不问「你们怎么质检？」。
3. **相邻类比**：库里没有的场景，按最接近的场景类比生成候选，并在推荐理由中标注「类比自 X 场景」——类比可能不准，标注给用户留出纠正的抓手。

**防护**：候选是猜测不是事实。用户回复表明整组候选方向性错误时（「我们不做 X，做的是 Y」），按用户那句话就地重出该题全组候选——重出不计入轮数预算。

## 回复解析约定

| 用户回复 | 解析 |
|---|---|
| 都按推荐 / 默认 / 你定 | 全部取 ★ 项 |
| 1A 2C | 未提及的题取 ★ 项 |
| 1A 2C 3默认 | 同上，3 显式取 ★ |
| 2AC | 多选题选 A+C |
| 1不对，我们是XX | 该题按自由文本覆盖，其余取 ★ |
| 部分回答后沉默 / 跑题 | 未答项取 ★，并写入产出的假设清单 |

解析后一行复述生效配置（「生效：1A 2C 3★」），不等二次确认，直接推进——复述是给用户的纠错窗口，不是新一轮审批。

## 生效假设标注

问不到、没答到、超预算的项，一律转假设放在产出头部：

```markdown
> **生效假设**（不符请指出编号）：
> H1 报告语言为中文（依据：对话语言）
> H2 数据以公开信息为限（依据：未提及内部数据源）
```

每条必须带推断依据；用户只需说「H2 不对」即可触发修正。

## 行业候选库

为「行业 know-how」类问题预置候选。这是提案的起点，不是正确答案——永远配逃生口。

### 电商 / 客服质检
- 常见维度：响应及时性、话术合规（禁语/敏感词）、问题解决率、情绪安抚、售后政策准确性
- 常见流程：抽检 → 逐维打分 → 违规标记 → 复核 → 周报

### 内容创作 / 新媒体
- 常见维度：选题类型（热点/常青）、平台风格（公众号长文/小红书种草/短视频脚本）、开头钩子、结构套路、合规红线
- 常见流程：选题 → 大纲 → 初稿 → 审校（事实+风格）→ 排版发布

### 数据分析 / 报告
- 常见维度：指标口径、对比基准（环比/同比/目标）、异常归因深度、可视化形式
- 常见流程：取数 → 清洗 → 分析 → 归因 → 结论先行成稿

### 竞品 / 市场研究
- 常见维度：产品功能、定价促销、营销动作、用户口碑、融资人事
- 常见来源：官网公告、新闻媒体、应用商店评价、社媒

### 招聘 / HR
- 常见维度：JD 要点提炼、简历筛选标准（硬性/加分）、面试评估维度、话术合规（就业歧视红线）

### 法务 / 合同审查
- 常见维度：主体与授权、权利义务对等、违约与赔偿、期限与终止、争议管辖
- 默认红线：只标注风险点与依据条款，不输出法律意见结论；此场景 S3 默认 =2

### 销售 / CRM 跟进
- 常见维度：线索分级标准、跟进节奏、话术库场景、异议处理、复盘字段

### 教育 / 培训
- 常见维度：受众水平、教学目标层次（识记/应用/分析）、课件形式、练习与测评方式

### 软件研发
- 常见维度：需求澄清清单、技术方案对比维度、代码规范、测试覆盖要求、评审清单

### 财务 / 对账
- 常见维度：数据源与口径、勾稽关系、差异容忍阈值、异常升级路径
- 此场景 S3 默认 =2，验证强度按 verification.md 配比原则的高档执行

库外场景按三源法第 3 条类比处理，并标注类比来源。
