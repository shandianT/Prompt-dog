# 验证设计与迭代闭环手册

S3≥1、设计闭环、或交付前自检时读。核心原则：验证是保险，保费不应超过标的——错误代价决定验证强度，而不是「越多越好」。

## 验收标准：自拟为主，成题为辅

验收标准区块 L2 及以上产物必有，由你按场景自拟、写成可二值判定的条目，用户按编号修正。**只有两类项可以成题**，其余一律预填为 H 假设随产物交付：

| 项 | 处理 |
|---|---|
| 错误代价 | 默认由你按场景推断并写 H；**仅当推断置信不高、且档位差异会改变验证装配**（中 vs 高决定要不要上对抗审查）时成题。L1 从不成题 |
| 场景化红线 | 「不编造数据/来源」是全场景默认，不问；**仅当行业库给不出默认红线**（如「不得提及未公开客户名」这类只有用户知道的）时成题，可多选 |
| 量化要求、格式、语气 | 永远不成题：按场景推测写成 H（如「H3 报告 800 字内、3–5 个要点（依据：周报惯例）」），用户改 H 号即可 |

成题时并入最后一轮澄清卡，不单独加轮；已在澄清轮确认过的项禁止重复问；用户明说「错了要出大事」，错误代价直接按高处理并写 H，不再问。无人值守时全部按 H 处理。

```markdown
**Q_ 这个任务的错误代价？**
- A. 低——错了改一下就行
- B. 中——错了会浪费别人时间
- C. 高——对外发布/影响决策，出错有实际损失
（★ 由你按场景推断预填到对应档位，并附一句推断理由；本题为穷尽枚举，不设「其他」）

**Q_ 红线（绝不允许出现的）？**（可多选）
- A. <场景化红线，如「提及未公开客户名」> ★推荐：<理由>
- B. <另一条场景化红线>
- C. 无其他红线
- D. 其他红线（一句话说明）
（「编造数据/来源」不列为选项——它是全场景默认红线，直接写进产物）
```

**错误代价的仲裁规则：你的场景推断与用户自评取其高**；用途不明时按「中」处理并写 H。用户选 A 但产出对外发布/供决策时，按 C 处理并说明一句原因。答案联动：澄清中途出现升险信号（如「受众改成管理层」），错误代价随之上调并告知。

## 按环节类型必带的验收项

每个环节（L3/L4 环节表、资产包 `验收清单.json`）除场景验收项外至少带一条本类型的必带项；不可二值判定的不算验收项：

| 环节产物类型 | 必带验收项 |
|---|---|
| 文档 / 文本（报告、标书章节、文案） | 关键论断有来源或标 [待核实]；引用附出处（页码 / 条款号 / 链接） |
| 结构化 / 机器可读（JSON、表格、矩阵） | 按 schema 校验通过：字段齐全、类型正确、下游环节能直接读 |
| 代码 | 类型检查与测试通过；跑不通的不落盘为成品 |
| 界面 | 在浏览器里实际打开并操作验证，截图留档 |
| 决定 / 分支（投不投、通过 / 退回） | 输出含明确的决定值与理由，每条出线都有去处 |
| 对外动作（发送、发布、提交、付款） | 动作前有人工确认点；确认前一切自动，确认后才执行 |
| 设计文档 / PRD（产品定义、stories） | 五问 30 秒可答；`design-mode.md` 门槛清单全过；stories 每条 ≥1 条本表对应类型的必带项 |
| 图（泳道流程图及其镜头） | 节点与线的计数与 flow JSON 一致；标记只用 卡点 / 缺口 / 待打通 三个名字；非顺序线有产物名；档位写入 H |

## 验证机制选型表

| 机制 | 触发信号 | 插入位置 | 成本 |
|---|---|---|---|
| 自我一致性 | 客观有正解 + 错误代价中高（计算、分类、抽取） | 生成时：3 次独立推理→投票 | 3 倍 token |
| 交叉核查 | 含可查证的事实陈述（数据、日期、引用），且环境有搜索/查询工具 | 生成后：调工具逐条核对 | 中，需搜索工具 |
| 来源引用强制 | 内容对外发布或供决策 | 生成中：无来源的关键论断标 [待核实] | 低 |
| 对抗审查 | 错误代价高的最终交付物 | 交付前：「专门找茬的反方」跑一遍列反驳清单，问题就地修正后交付 | 中，1 轮额外调用 |
| 人工确认点 | **只有不可逆动作**：发送、发布、删除、付款、提交、签署 | 该动作执行前暂停并出确认卡；确认点之前的一切自动完成，无人回复时停在确认点、不自动执行 | 极低，但打断流程 |

**配比原则**：代价低 → 最多一种轻量机制；代价中 → 1–2 种；代价高 → 来源引用 + 对抗审查，含可查证事实陈述时加交叉核查。**人工确认点不按错误代价配，只按有没有不可逆动作配**——高风险但没有不可逆动作的任务（写报告、审合同、出方案）靠「对抗审查 + 交付给人复核」兜底，产物里不插入「暂停等确认」环节，否则每次运行都卡在等人。

**环境封顶**：验证强度不能超过运行环境的能力。环境无搜索工具时，交叉核查降级为「关键论断标 [待核实] + 交付附人工核对清单」并写入 H；环境无法多次调用时，自我一致性降级为「一次推理 + 自我修正」。不设计环境里不存在的验证环节。图同样封顶：档位按 process-rebuild.md「图档位由环境决定」三档，任何画图技能都不是必备依赖，缺了降档不缺图。向用户呈现严格档选项时标注成本（「耗时约多一倍」），让他有知情选择权。

## 会话内试跑（交付前质检，L2 以上必做）

1. 默认自行构造样例输入并标注「试跑样例」，不向用户索要——别让交付卡在等材料上；交付时附一句「有真实样例贴来，我可再跑一遍替换结论」。
2. 用生成的提示词（L2 取关键步骤、L3/L4 取首环节）实际跑一遍。有工具就真实执行（写文件、调用工具都可以）；无法在会话内执行的环节（需外部系统、定时触发、人工动作）改为**静态走查**：检查上游输出是否覆盖下游输入的每个字段（数据契约闭合）、每个验证点是否可二值判定。
3. 对照验收标准逐条检查输出：格式是否符合数据契约、标准是否可达。
4. 不达标就地修正提示词，最多修 2 轮；仍不达标说明设计有问题，回到构建阶段重设计**一次**；重设计后仍不达标 → 照常交付，未达标项写进「未达标清单」与 H 假设，不再继续。**试跑是质检，不是交付的阻塞点。**
5. 交付时附一句试跑结论（「已用样例输入试跑，验收标准 N/N 通过」；有未达标项时列出）。

试跑是你在会话里做的质检，别与产物内嵌的运行时闭环混淆。

## 诊断分支表（症状 → 根因 → 精调 → 回到哪一步）

评估未通过时先归类症状再动手，禁止盲目重写：

| 症状 | 根因判断 | 精调策略 | 回到哪一步 |
|---|---|---|---|
| 结论/逻辑/计算错 | 推理深度不足 | 加 CoT；仍错→自我修正；需外部事实→ReAct | 回构建，改提示词 |
| 结构/字段/语气不对 | 输出控制缺失 | 输出格式化（给 schema）+ 响应预填充；创造性失衡→参数调优 | 回构建，只改输出段 |
| 长输入后忘记前文要求 | 上下文丢失 | 关键指令置尾、分块 + 提示链 | 回架构，可能升级 |
| 大体对、细节瑕疵 | 无结构性问题 | 建设性引导：对话中直接微调 | 就地修，不回退 |
| 反复摇摆、时对时错 | 稳定性不足 | 少样本补例 + 自我一致性 | 回构建 |
| 修改后复杂度实质变化 | 判级过期 | 重算六信号 | 回判级（见 SKILL.md 变更与重判级） |

## 终止条件模板（写入每个 L3/L4 产物）

```markdown
## 循环终止条件
- 轮次定义：第 1 轮 = 首次执行全链并按验收标准打钩；之后每轮 = 诊断→精调→只重跑被精调的环节及其下游→再打钩
- 最大轮数：3 轮
- 收敛通过：验收标准全部打钩 → 交付
- 止损：某一轮精调后打钩数没有增加 → 立即停止自动迭代（根因判断错了，继续硬调是空转）
- 止损后同时交付三样：①已达标部分 ②未达标项清单 ③卡点报告（症状 / 已试策略 / 建议人工介入点）
- 人工确认点：仅在不可逆动作（发送 / 发布 / 提交）前暂停；其余环节不等人
```

「无改善」的唯一度量是验收标准打钩数——不用「感觉没变好」这类不可判定的表述。最大轮数是 3，所以止损线必须是「一轮不增加」：写成「连续两轮不增加」的话它只会在第 3 轮末尾触发，与最大轮数重合，等于没有止损。

## 诊断改进模式的回归对照

改进现有提示词交付时，附一个最小回归样例：同一测试输入下「原版预期表现 vs 改进版预期表现」各一句，并建议用户用自己的真实输入各跑一次对比——改进必须可验证，不能只靠评分数字。

## 交付前自检清单（每次交付都跑）

```markdown
□ 产出形态与复杂度等级匹配（没有用 L3 大炮打 L1 蚊子）
□ 验收标准区块存在（S3=0 时为你自拟的标准，已在 H 里标注）
□ 错误代价≥中的内容已内嵌对应验证机制，且机制不超出运行环境能力
□ L3/L4 含内嵌闭环且终止条件写死、止损线是「一轮不增加」、止损后三样同时交付
□ 人工确认点只出现在不可逆动作前；没有「每步等确认」「输出后等继续」
□ 无人回复时产物也能跑完：每张卡片、每个分叉都有 ★ 默认路径
□ 全程未出现连续开放式提问；每张卡片都有推荐默认值；本次回复要么交付要么出卡
□ 提示词本体自含（拿走即用，不依赖本次对话上下文）
□ 头部有版本行 + 生效假设清单（每条带依据）
□ L2 以上已会话内试跑并附结论（含未达标清单，如有）
□ 编排产物只使用运行环境真实存在的能力
□ 每个环节一个上下文能做完；会无人运行的资产包含 验收清单.json，每环节至少一条按类型必带的验收项
```
