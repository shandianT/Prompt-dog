# 策略地图：提示词策略全量档案

「信号→策略」的触发路由在 `complexity-routing.md`；本文件是策略本身的档案——需要某策略的实施细节、想解释「为什么用它」、或诊断时怀疑选错了策略时读。

## 五阶段流程（策略的宿主）

1. **规划与架构**：明确目标约束 → 评估复杂度 → 选架构（单一提示词 / 提示链 / 多智能体）
2. **基础构建**：人设、正面引导、结构化打底 → 情境启动、明确性填充 → 选零样本或少样本
3. **执行与评估**：运行并对照验收标准评估
4. **诊断与精调**：按症状归因，选对应策略修复（见 verification.md 诊断分支表）
5. **工程化管理**：文档化 → 持续评估 → 必要时 APE

## 策略档案

### 基础构建类

| 策略 | 核心思想 | 理想场景 | 何时慎用 |
|---|---|---|---|
| 零样本 | 直接指令，无示例 | 常见任务、总结、翻译 | 复杂推理、特定格式 |
| 少样本/单样本 | 提供示例，引导模式 | 特定格式、风格模仿、主观分类 | 任务简单、示例质量差 |
| 人设 | 分配专家角色 | 专业分析、代码审查、营销文案 | 仅为装饰、非专业需求 |
| 明确性 | 消除模糊，指令清晰 | 高精度任务、量化要求、限定范围 | 会限制创造力时、过度指挥 |
| 情境启动 | 提供背景信息 | 分析特定文档、会议总结、定制回应 | 背景信息有误或无关 |
| 结构化 | 分隔符/标签区分内容 | 长提示词、区分指令与数据 | 简单短提示词 |
| 正面引导 | 多说「做什么」 | 规范行为、控制风格、最佳实践 | 硬性安全/法律限制（此时要明说禁止） |

### 高级推理类

| 策略 | 核心思想 | 理想场景 | 何时慎用 |
|---|---|---|---|
| 思维链 CoT | 分步思考，展示过程 | 逻辑推理、数学、复杂分析 | 简单任务、创意生成 |
| 自我一致性 | 多次推理，投票取优 | 高风险高精度、有客观答案 | 创意任务、实时应用（3 倍成本） |
| 思维树 ToT | 探索多路径并回溯 | 战略规划、创意写作、方案探索 | 任务有清晰线性解法 |
| 退一步 | 先问抽象问题 | 突破思维僵局、寻求创意 | 问题已足够清晰 |
| 自我修正 | 内置审查改进循环 | 代码生成、查漏补缺、稳健性 | 简单一次性任务 |
| ReAct | 推理 + 外部工具 | 实时信息、事实核查、调 API | 无需外部信息的任务 |

### 工作流架构类

| 策略 | 核心思想 | 理想场景 | 何时慎用 |
|---|---|---|---|
| 提示链 | 复杂任务分解为环节 | 多阶段工作流、报告生成、避免巨型提示词 | 单一简单任务 |
| 多智能体 | 组建 AI 团队协同 | 跨领域协作、复杂项目、角色制衡 | 单一 AI 可胜任时 |
| 建设性引导 | 迭代对话，协同精炼 | 打磨初稿、复杂创意、持续协作 | 简单一次性任务 |

### 输出与行为控制类

| 策略 | 核心思想 | 理想场景 | 何时慎用 |
|---|---|---|---|
| 输出格式化 | 强制机器可读结构 | 数据管道、API 响应、JSON/XML | 自由文本、散文输出 |
| 响应预填充 | 预写 AI 回复开头 | 强制 JSON、触发 CoT、控制语气 | 可能过度限制创造力 |
| 参数调优 | 调 Temperature/Top-P | 低温取事实、高温取创意 | 不理解参数影响、环境不支持 |

### 工程化与特定领域类

| 策略 | 核心思想 | 理想场景 | 何时慎用 |
|---|---|---|---|
| 长上下文 | 优化超长输入 | 分析报告、代码库、长文档 | 短查询 |
| 代码提示 | 软件工程精确提示 | 代码生成、调试、翻译 | 缺乏上下文或错误信息时先补齐 |
| 自动提示工程 APE | AI 生成并优化提示词 | 探索提示词变体、自动化优化 | 设置复杂、计算成本高 |
| 文档化 | 像代码一样版本化 | 生产级应用、团队协作、可复现 | 一次性非复用测试 |

## 常用组合

- **CoT + 自我一致性**：先让推理可见，再用投票消除单次波动——高风险计算/分类的标配。
- **ReAct + 来源强制**：工具取数时同步记录来源，验证环节才有抓手。
- **提示链 + 输出格式化**：环节间数据契约用 JSON schema 锁死，下游环节才不用猜上游格式。
- **人设 + 少样本**：角色定基调，示例定格式，风格类任务双保险。
- **多智能体 + 自我修正**：产出角色与审查角色分离，比同一角色自查更能发现问题。
- **文档化 + APE**：先有版本基线，再自动探索变体，否则优化结果无从对比。

## 反模式（诊断时先排查）

- 简单任务堆高级策略：L1 任务上 CoT+自我一致性，慢且贵，输出还可能过度思考。
- 用多智能体掩盖提示词写不清：单角色说不明白的事，拆成三个角色只会错三次。
- 无验收标准就上闭环：循环没有收敛判据，永远在「感觉不够好」里空转。
- 把参数调优当万能药：温度解决不了指令模糊。
