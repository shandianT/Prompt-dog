# 无人上岗：状态文件、循环与复盘两级制

**何时读**：产物是资产包（场景重复使用 + 有文件系统）**且**会在无人交互下跑——定时、批量、被脚本或另一个 agent 调用、环节数 ≥3 的长任务。一次性任务、环节 ≤2、纯对话环境不读。机制借鉴 snarktank/ralph（MIT）：agent 的记忆不在上下文里，在仓库文件里；每轮开一个新上下文，读文件、做一件事、写回去。

## 三份文件就是记忆

| 文件 | 角色 | 谁写、何时写 |
|---|---|---|
| `验收清单.json` | 任务状态：环节、验收项、`passes` | 上岗时生成；每轮结束写回 |
| `复盘/日志.md` | 追加式日志；顶部「已知规律」段 | 每轮追加一条；规律随时抬升到顶部 |
| `AGENTS.md` | 路由 + 「已知规律」 | 改版时从日志顶部抬升，不每轮改 |

有 git 就用：每完成一个环节提交一次，信息 `feat: 环节N - <名称>`。git 历史是第四份记忆。

## 验收清单.json

```json
{
  "场景": "标书撰写", "版本": "1.2", "任务": "<项目名>", "输入": ["招标文件/<文件名>.pdf"],
  "环节": [
    { "id": 1, "名称": "招标解析与废标项", "依赖": [], "提示词": "prompts/环节1-招标解析与废标项.md",
      "输出": "输出/<项目名>/01-解析与废标项.md",
      "验收": [ { "项": "废标项逐条打钩，存疑项置顶警告", "passes": false },
                { "项": "引用招标文件均附页码或条款号", "passes": false } ],
      "passes": false, "备注": "" }
  ],
  "轮次": 0, "最大轮次": 3, "状态": "进行中", "不可逆动作": ["递交"]
}
```

规则：验收项必须可二值判定；每环节至少含一条该类型的必带项（`verification.md`「按环节类型必带的验收项」）；每轮只改 `passes` / `备注` / `轮次` / `状态`，不改结构；`状态` 三值：`进行中` / `交付` / `止损`。

## 环节尺寸规则（建包时就要遵守）

- **一个环节一个上下文能做完**：输入材料 + 提示词 + 输出合计不超过上下文的三分之一。超了就拆——按产物拆（分章撰写 → 每章一个环节实例）、按动作拆（检索 → 撰写）、按对象拆（每份合同一个实例）。
- **依赖先行**：环节顺序就是产物依赖顺序；环节 N 只读环节 N−1 的产物与素材库，不回读全链。
- **自含**：每个环节的提示词自带人设、输入契约、输出契约、完成前自查，不依赖会话记忆。

## 上岗循环（每轮一个全新上下文）

1. 读 `AGENTS.md` → `验收清单.json` → `复盘/日志.md` 顶部「已知规律」（不读日志全文）
2. 取第一个 `passes=false` 且依赖全部 `passes=true` 的环节；没有这样的环节且仍有未过项 → 进入闭环轮：按 `verification.md` 诊断分支表归因，只精调并重跑该环节及其下游
3. 只做这一个环节，产物落盘到 `输出/`
4. 对照该环节的验收项逐条判 `passes`，写回 `验收清单.json`
5. 追加日志一条；发现通用规律 → 写进日志顶部「已知规律」
6. 有 git 则提交
7. 输出停机标记，或正常结束让下一轮接手

| 情形 | 输出 | 循环动作 |
|---|---|---|
| 全部环节 `passes=true` | `<promise>交付</promise>` + 交付物路径 | 退出，`状态=交付` |
| 闭环轮打钩数没有增加，或轮次达上限 | `<promise>止损</promise>` + 已达标部分 + 未达标清单 + 卡点报告 | 退出，`状态=止损` |
| 下一步是不可逆动作（`不可逆动作` 列表内） | `<promise>待确认</promise>` + 确认卡 | 退出，人回复后重启 |
| 其他 | 无标记 | 下一轮继续 |

最大轮数 = 环节数 + 最大闭环轮次；到顶仍未交付按止损处理。人工确认点只有不可逆动作一种，其余分叉全部走 ★ 默认路径。

### 循环脚本模板（`上岗.sh`，放在资产包根目录）

```bash
#!/bin/bash
# 用法：./上岗.sh [--tool claude|codex] [最大轮数]
TOOL=claude; MAX=0
while [[ $# -gt 0 ]]; do case $1 in --tool) TOOL=$2; shift 2;; *) MAX=$1; shift;; esac; done
cd "$(dirname "$0")"
[ "$MAX" -gt 0 ] || MAX=$(python3 -c "import json;d=json.load(open('验收清单.json',encoding='utf-8'));print(len(d['环节'])+d.get('最大轮次',3))")
PROMPT="读取 AGENTS.md，按「无人上岗」规则执行 验收清单.json 里下一个未通过的环节；只做一个环节，写回清单并追加日志。"
for i in $(seq 1 "$MAX"); do
  echo "== 第 $i/$MAX 轮 ($TOOL)"
  if [ "$TOOL" = claude ]; then OUT=$(claude --print "$PROMPT" 2>&1 | tee /dev/stderr); else OUT=$(codex exec "$PROMPT" 2>&1 | tee /dev/stderr); fi
  echo "$OUT" | grep -q "<promise>交付</promise>" && { echo "全部环节通过"; exit 0; }
  echo "$OUT" | grep -q "<promise>止损</promise>" && { echo "止损，见 复盘/日志.md 与卡点报告"; exit 2; }
  echo "$OUT" | grep -q "<promise>待确认</promise>" && { echo "停在人工确认点，回复后重跑"; exit 3; }
  sleep 2
done
echo "到达最大轮数仍未交付，按止损处理"; exit 1
```

权限：脚本不加「跳过全部权限」类参数；工具需要的授权按环境正常配置，不可逆动作靠 `<promise>待确认</promise>` 停下。

## 复盘两级制

**第一级：日志，只追加不改写。** 每轮一条：

```markdown
## 2026-09-08 14:00 · 环节 2 评分拆解与应答矩阵
- 做了什么：应答矩阵 37 行 → 输出/<项目名>/02-应答矩阵.md
- 验收：2/2 通过
- 给下一轮的教训：评分细则里「同类项目业绩」按近三年计，素材库要按年份筛
```

**第二级：已知规律，日志顶部一段，≤10 条。** 只放与本次任务无关、下次还会用的规律；满了就合并。改版时把这段抬升进 `AGENTS.md`「已知规律」，日志顶部清空重新累积。

不许写进「已知规律」：单次任务的细节（项目名、页码）、临时调试记录、已在日志正文里的内容。判断句式：「下一次做别的项目还用得上吗？」用不上就留在日志正文。

复盘模板（`复盘/复盘模板.md`）负责按指标回填与提示词修改建议；日志负责过程与教训。两者不重复：模板在任务结束后填一次，日志每轮追加。

## 何时不用

一次性任务、环节 ≤2、纯对话环境、每步都需要人看的流程——直接按主循环交付单份文档，不建状态文件与循环。飞轮只对重复的事有价值。
