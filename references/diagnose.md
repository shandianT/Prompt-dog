# 诊断模式：改进现有提示词

用户贴来一段现有提示词求评价/改进时用本流程。两步走：**先零提问打分，再一张卡片确认**——用户全程最多做一次选择题。

## 第一步：零提问诊断

拿到提示词直接评分，不问任何问题——先给价值，再要信息。按十维打分（1–10），维度沿用「药剂师」原版定义：

| 维度 | 看什么 |
|---|---|
| 明确性 Clarity | 指令是否清晰无歧义，信息是否足以引导有意义的输出 |
| 相关性 Relevance | 是否与目标任务紧密相关，能否引导领域相关的响应 |
| 完整性 Completeness | 是否包含引导全面回答的全部必要元素（人设/背景/格式/边界） |
| 中立性 Neutrality | 是否避免了不当引导与偏见（刻意的立场设定除外） |
| 创造性 Creativity | 需要创意的任务里，是否激发新颖思考 |
| 结构 Structure | 结构是否引导模型沿预期路径生成（分段、分隔符、顺序） |
| 语法 Grammar | 语法是否正确 |
| 流畅性 Fluency | 语言是否自然流畅 |
| 目标对齐 Alignment | 各部分是否服务同一个目标，有无自相矛盾 |
| 可测试性 Testability | 输出好坏是否可被一致地判定 |

输出格式：

```markdown
## 诊断结果：<总分>/100

| 维度 | 得分 | 一句话依据 |
|---|---|---|
（十行）

**一句话结论**：<最大的问题是什么，改掉后预期提升什么>
```

打分要严格拉开差距——处处 7 分的评分没有信息量。

## 第二步：一张卡片确认改进方向

只对**得分最低的 2–3 个维度**出一张选择题卡片，每题预填基于提示词内容的推测：

```markdown
## 确认卡片（仅 1 轮）
回复如「1A 2B」，或「都按推荐」。

**Q1 「完整性」仅 3 分——缺人设与输出边界。你希望它扮演：**
- A. <据提示词内容推测的角色> ★推荐：<理由>
- B. <备选角色>
- C. 保持现状
- D. 其他（一句话）

**Q2 「可测试性」仅 4 分。输出好坏你打算怎么判断：**
- A. <推测的验收方式> ★推荐：<理由>
- B. …
```

卡片规则同 `clarify-cards.md`（逃生口、★带理由、解析约定）。

## 第三步：输出改进

确认后输出三部分：

1. **三条改进建议**，每条按此格式：
   - 建议N：<建议内容>
   - 原文：<针对提示词中的哪段>
   - 机制：<为什么这样改有效——底层原理，如「分隔符降低指令与数据混淆」>
2. **改进版全文**，改动处加粗，保持用户原始意图不变。
3. **回归对照**：同一测试输入下「原版预期表现 vs 改进版预期表现」各一句，建议用户用真实输入各跑一次验证——改进必须可验证，不能只靠分数。

## 升级出口

诊断中发现任务本身超出单提示词能力（需要工具、定时触发、多角色、多步流程——即六信号 S1/S4/S5 有 2 分项）时：先照常完成本次改进交付，再用一句话告知「这个任务用工作流做会更稳，需要的话我按 L2/L3 方案重新设计」，用户同意后转入主循环重新判级。不强推升级——用户要的是改提示词，先满足。
