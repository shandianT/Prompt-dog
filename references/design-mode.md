# 设计模式：从一个产品想法到能开工的三件套

**何时读**：入口路由判为「设计」——用户给的是一个要做的产品 / 功能 / 界面想法，或明说要产品定义、PRD、设计文档、原型。不判级：先出三件套与图，`stories.json` 里标「转主循环」的故事再回主循环判级、建包。只贴一段流程要图 → 流程重构；只要一段提示词 → 新建。

**产物**：三件套 + 图。一页产品定义、`stories.json`（可执行的 PRD）、SPEC 骨架（有界面时才要）；骨架与字段见 `output-templates.md`「设计模式产物」，缺节即不合格。范例：`design/workbench/` 的 `产品定义.md`、`stories.json`、`SPEC.md`（已按下方门槛逐条核对，2026-09-08）。

## 步骤

**第 0 步：材料先行，不问先写。** 用户给了材料（竞品、截图、现有流程、聊天记录、投诉记录）→ 从材料抽用户、场景、现状痛点，每条记来源；没材料 → 按行业候选库里的同类产品预填，写「H 用户与场景按行业惯例推断」。没有空白文档：永远先给一页可纠错的定义。

**第 1 步：五问首行，验收先于撰写。** 动笔前先把五问答成一行：① 为谁 ② 解决什么 ③ 怎么算成功 ④ 不做什么 ⑤ 先做哪条。答不出的那问不硬编，写 H 号并附「怎么验 / 验不过怎么办」。这一行既是产品定义的首行，也是交付前的验收口径。

**第 2 步：一页产品定义。** 按 `output-templates.md` 骨架写；一页写不下就是范围没收住，先砍再写。

**第 3 步：`stories.json`。** 按依赖排序；每条一个上下文能做完（尺寸规则见 `run-loop.md`）；每条验收 ≥2 条可二值判定，其中 ≥1 条是 `verification.md`「按环节类型必带的验收项」里对应类型的项；产品定义的每个核心场景至少被一条故事覆盖；要建 Agent 的故事在描述里写「转主循环」。`passes` 由搭建者验收后置 true，不驱动上岗循环——上岗只认建包时按 `run-loop.md` 生成的 `验收清单.json`。

**第 4 步：图。** 只在 ≥2 个角色有交接、或产品里含一段流程时配泳道流程图：从 flow JSON 渲染，档位由环境决定（`process-rebuild.md`「图档位由环境决定」）。图顶的五问数字（自动 / 人 / 卡点 / 缺口 / 待打通）是流程图的计数，与三件套的五问首行无关。单角色工具不配图；有界面时给屏幕清单表，不画屏幕流图。

**第 5 步：四视角找茬，就地修。** 每个视角至少一条反驳，处理方式三选一：采纳 / 写入 H / 驳回附理由。

| 视角 | 问什么 |
|---|---|
| 老板 | 30 秒答不出五问中的哪一问 |
| 搭建者 | 按 `stories.json` 第一条今天能开工吗，缺什么输入 |
| 执行者 | 跑完知道停在哪吗（人审 / 人定在哪一步） |
| 反方 | 哪条 H 最先垮；哪条成功指标不能从文件回填（对照 `复盘模板.md`） |

**第 6 步：交付。** 顺序固定：五问首行 → 一页产品定义 → `stories.json` → 图 → H 假设 → 可选纠错卡。话术：「三件套按材料先出好了；说编号（H 号或故事号）就能改，说『按这个建』就从第一条故事开始」。

## 唯一的一张卡（只在架构级不确定时出，否则预填交付）

| 题 | 候选 | ★ 规则 |
|---|---|---|
| 楔子：第一条故事 | A. 原话里的痛点 ★ / B. 最小可演示路径 / C. 用户指定 | 原话有痛点取 A，否则 B |

SPEC 骨架有无按「原话有界面或 ≥3 屏」推断写 H；图档位、受众、篇幅、语气一律写 H，不成题；用户明说「只要故事清单」按用户覆盖办，记 H0。

## 门槛（交付前逐条打钩，写不成打钩项的不算）

```markdown
□ 五问首行五段各非空，或带 H 号
□ 一句话 ≤40 字，含对象与动作
□ 用户表每行三列齐：角色 / 要什么 / 成功的样子
□ 每条成功指标有数字与判法，没有「好看 / 清晰 / 合理」类词
□ 非目标 ≥3 条，且没有一条出现在 stories 里
□ 每条 H 有「怎么验 / 验不过怎么办」
□ 待拍板 ≤6 条，每条带 ★ 建议
□ stories 每条 ≥2 条二值验收、≥1 条类型必带项、一个上下文能做完；要建 Agent 的故事描述含「转主循环」
□ 产品定义的每个核心场景在 stories 里至少一条
□ 四视角各 ≥1 条反驳已处理
□ 章节骨架与 output-templates.md「设计模式产物」一致
□ 有图时图档位已写入 H
```

## 与其他模式的交接

| 上游 → 下游 | 交接产物 | 启动条件 |
|---|---|---|
| 流程重构 → 设计 | 流程图 JSON | 用户要产品 / 界面，不只要图 |
| 设计 → 流程重构 | 流程图 JSON | 用户要看卡点、缺口、待打通 |
| 设计 → 新建（主循环） | `stories.json` 里第一条 `passes=false` 且描述含「转主循环」的故事 | 「按这个建」；无人时取楔子 ★ 那条 |
