# 设计模式：从一个产品想法到能开工的三件套

**何时读**：入口路由判为「设计」——用户给的是一个要做的产品 / 功能 / 界面想法，或明说要设计文档、PRD、原型。不判级：先出三件套与图，`stories.json` 里每条要建 Agent 的故事再转主循环判级、建包。只贴一段流程要图 → 流程重构；只要一段提示词 → 新建。

**产物一句话**：三件套——一页产品定义（为谁 / 解决什么 / 怎么算成功 / 不做什么 / 先做哪条）、`stories.json`（可执行的 PRD：按依赖排序的小故事，每条一个上下文能做完，验收可二值判定）、SPEC 骨架（有界面时才要）。范例就是本仓库 `design/workbench/` 里的 `产品定义.md`、`stories.json`、`SPEC.md`，骨架见 `output-templates.md`「设计模式产物」；缺节即不合格。图按环境档位随三件套交付。

## 五问即验收

30 秒从一页产品定义答出：① 为谁 ② 解决什么 ③ 怎么算成功 ④ 不做什么 ⑤ 先做哪条。**验收先于撰写**：动笔前先把五问答案填成首行；答不出的那问不硬编，转 H 假设并附「怎么验 / 验不过怎么办」。

## 步骤

**第 0 步：材料先行，不问先写。** 用户给了材料（竞品、截图、现有流程、聊天记录、投诉记录）→ 从材料抽用户、场景、现状痛点，每条记来源；没材料 → 按行业候选库里的同类产品预填，写「H 用户与场景按行业惯例推断」。没有空白文档：永远先给一页可纠错的定义。

**第 1 步：五问首行。** 一行五段，答不出的写 H。

**第 2 步：一页产品定义。** 骨架固定：一句话 → 用户表（角色 / 要什么 / 成功的样子）→ 已建议的决定（★）→ 核心场景（编号）→ 非目标 → 假设与验证（编号 / 假设 / 怎么验 / 验不过怎么办）→ 里程碑 → 成功指标（数字 + 判法）→ 待拍板（≤6，每条 ★）。一页写不下就是范围没收住，先砍再写。

**第 3 步：`stories.json`。** 按依赖排序；每条一个上下文能做完（尺寸规则见 `run-loop.md`）；每条验收 ≥2 条可二值判定，其中 ≥1 条是 `verification.md`「按环节类型必带的验收项」里对应类型的项；产品定义的每个核心场景至少被一条故事覆盖；要建 Agent 的故事在描述里写明「转主循环」。

**第 4 步：图。** 只在 ≥2 个角色有交接、或产品里含一段流程时配泳道流程图，从 flow JSON 渲染，档位由环境决定（`process-rebuild.md`「图档位由环境决定」）；单角色工具不配图。有界面时给屏幕清单表，不画屏幕流图。

**第 5 步：对抗审查四视角，就地修。** 每个视角至少一条反驳，处理方式三选一：采纳 / 写入 H / 驳回附理由。

| 视角 | 问什么 |
|---|---|
| 老板 | 30 秒答不出五问中的哪一问 |
| 搭建者 | 按 `stories.json` 第一条今天能开工吗，缺什么输入 |
| 执行者 | 跑完知道停在哪吗（人审 / 人定在哪一步） |
| 反方 | 哪条 H 最先垮；哪条成功指标不能从文件回填（对照 `复盘模板.md`） |

**第 6 步：交付。** 顺序固定：五问首行 → 一页产品定义 → `stories.json` → 图 → H 假设 → 可选纠错卡。话术：「三件套按材料先出好了；说编号（H 号或故事号）就能改，说『按这个建』就从第一条故事开始」。

## 唯一的一张卡（只在架构级不确定时出，否则预填交付）

| 题 | 候选 | ★ 规则 |
|---|---|---|
| 深度 | A. 产品定义 + stories ★ / B. 加 SPEC 骨架 / C. 只要 stories | 原话有界面或 ≥3 屏 → B；「直接开工」→ C |
| 楔子：第一条故事 | A. 原话里的痛点 ★ / B. 最小可演示路径 / C. 用户指定 | 原话有痛点取 A，否则 B |

图档位、受众、篇幅、语气不成题：图档位由环境探测写 H；三件套本来同时服务老板、搭建者、执行者。用户说「直接做」→ 全 ★。

## 门槛（交付前逐条打钩，写不成打钩项的不算）

```markdown
□ 一句话 ≤40 字，含对象与动作
□ 用户表每行三列齐：角色 / 要什么 / 成功的样子
□ 每条成功指标有数字与判法，没有「好看 / 清晰 / 合理」类词
□ 非目标 ≥3 条，且没有一条出现在 stories 里
□ 每条 H 有「怎么验 / 验不过怎么办」
□ 待拍板 ≤6 条，每条带 ★ 建议
□ stories 每条 ≥2 条二值验收、≥1 条类型必带项、无环依赖、一个上下文能做完
□ 产品定义的每个核心场景在 stories 里至少一条
□ 四视角各 ≥1 条反驳已处理
□ 章节骨架与 output-templates.md「设计模式产物」一致
□ 有图时图档位已写入 H
```

## 无人回复

沉默、跳过、「直接做」→ 全 ★，三件套照常交付，本该出卡的题折叠进 H。三件套不建复盘目录、不回流；同类产品第 2 次出现，才把上一份当范例抬升到 `design/`。

## 与其他模式的交接

| 上游 → 下游 | 交接产物 | 启动条件 |
|---|---|---|
| 流程重构 → 设计 | 流程图 JSON | 用户要产品 / 界面，不只要图 |
| 设计 → 流程重构 | 流程图 JSON | 用户要看卡点、缺口、待打通 |
| 设计 → 新建（主循环） | `stories.json` 第一条 `passes=false` 且描述含「转主循环」的故事 | 「按这个建」；无人时取楔子 ★ 那条 |

`stories.json` 不是 `验收清单.json`：上岗只认后者，由建包阶段按 `run-loop.md` 生成。
