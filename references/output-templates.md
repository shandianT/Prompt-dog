# 产物模板（L1–L4）

按判级结果抄对应模板。所有产物共同要求：自含（拿走即用，不依赖本次对话）、头部带版本行与生效假设清单、交付话术以「这份产出直接发给你的 Agent 即可用；想调整，说编号（环节号或假设 H 号）就行」收尾——不用「上面/下面」这类方位词。

## 通用头部区块

```markdown
# <产物名称>  v1.0（YYYY-MM-DD）

> **生效假设**（不符请指出编号）：
> H1 <假设>（依据：<推断来源>）
> H2 <假设>（依据：<推断来源>）
```

## L1：优化提示词

```markdown
<通用头部>

## 提示词（复制下面整段使用）

你是<人设：具体的专家角色>。

背景：<情境启动：任务背景与输入说明>

任务：<正面指令：做什么，量化边界>
<若格式特殊，附 1–2 个示例（少样本）>

输出要求：<格式、长度、语气约束>
<S3=1 时附：完成前自查——<验收标准 2–3 条>>

---
使用说明：把 <占位符> 替换为你的实际内容后发送即可。
```

## L2：步骤化 SOP

```markdown
<通用头部>

## 验收标准（S3≥1 时必有）
- [ ] <可二值判定的标准 1>
- [ ] <标准 2>

- 目的：<为什么有这一步>

- 检查点：<进入下一步前确认什么；不满足时的处理>

### 步骤 2：<名称>

| 症状 | 处理 |
|---|---|
| <症状> | <重试/调整哪一步/升级人工> |
```

## 资产包形态（运行环境有文件系统时，L3/L4 优先采用）

产物不是单份文档，而是一个可整体拖入任意 Agent 工作区的文件夹——skill 是资产的存放形态，agent 是资产的上岗形态：

```text
<场景名>Agent/
├── AGENTS.md          路由 + 渐进式加载规则（执行到环节 N 才读环节 N 的文件）
├── <主控>.md          系统提示词 / 输入方式 / 验收标准 / 环节表 / 闭环终止（≤3KB）
├── prompts/           每环节一个提示词文件，按需加载
├── templates/         交付模板，交付环节才读
├── 启动指令.md         固定触发话术（单次 / 批量 / 复盘 / 回归，用户复制改参数即用）
├── 使用说明.md         小白上手 + 上线三道关（保密 / 回归 / 边界）
├── CHANGELOG.md       版本变更记录
├── 复盘/              使用后按指标回填（漏报 / 误报 / 新场景 → 提示词改进建议）
├── 回归测试/           历史样本 + 预期结果；改版必跑，设发布门槛
└── <输入>/ <输出>/     工作目录，交付物统一落盘命名
```

设计原则：内容平台无关（不写任何平台私有格式），换平台整个文件夹原样搬走；复盘与回归目录是资产增值的飞轮，必须随包交付而非事后补。

## 上手指南区块（每份产物末尾必附）

面向完全不懂提示词的使用者，只写动作不写原理，3–6 步、每步一个动作：

```markdown
## 上手指南
1. 复制上方「<产物主体名>」整段，贴到 <目标位置：对话框 / 系统提示词框 / AGENTS.md>
2. 替换占位符：<逐个列出 <占位符> 该填什么，给一个填写示例>
3. 用真实例子测试：发送 <样例动作>，看到 <预期效果> 即生效
4. 不满意时：回「H<编号> 不对，实际是…」或「第 <X> 步改成…」，只改该处
```

L2/L3 产物的指南改为执行导引：从步骤/环节 1 开始逐段写明——先贴哪段、输入给什么、输出检查什么、通过才进下一步；每步附「看到什么算成功」。
