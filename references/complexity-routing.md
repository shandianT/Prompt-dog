# 复杂度判级锚点与策略路由

六信号量表本体在 SKILL.md，本文件是它的打分锚点、边界仲裁和策略路由表。判级拿不准、或进入构建需要装配策略时读。

## 六信号打分锚点

- **S1 步骤数**：数的是「换一种思维方式的次数」，不是句子数。翻译+润色算一步（同一动作域）；采集→提取→对比→成稿是四步。
- **S2 领域知识**：0 = 任何受过教育的人都能做（翻译、总结、改写）；1 = 需要知道行业常见做法才能做对（质检维度、周报惯例、JD 结构）——特征：行业候选库里查得到；2 = 需要执业级判断（法律风险定性、医疗建议、审计结论）——特征：错了要专业人士才看得出来。
- **S3 准确性风险**：0 = 错了改一下就行（草稿、灵感）；1 = 错了浪费别人时间（团队周报、内部分析）；2 = 错了有实际损失（对外发布、供决策、合规文书）。用途不明（自用还是给别人看）时取低分并用假设对冲——「取其高」仲裁只对已知对外/供决策的场景生效。
- **S4 外部依赖**：0 = 输入全在对话里；1 = 需要一次搜索或一个工具；2 = 多工具协同、定时触发、跨系统读写。
- **S5 角色协作**：0 = 一个视角写完；1 = 写完需要一个「审查者」视角把关；2 = 需要多个专业角色各自产出再协作。
- **S6 产出结构**：0 = 自由文本，轻量格式约束（「三条要点」「500 字内」）也算 0；1 = 固定版式（模板化报告）；2 = 机器可读（JSON/表格）且有下游程序或流程消费。

## 定级、越级与降级

- 0–2 → **L1** 优化提示词；3–5 → **L2** 步骤化 SOP；6–8 → **L3** 提示链；9–12 → **L4** 多智能体编排。
- 越级信号（无视总分直接抬级）：含循环迭代 → 至少 L3；多角色独立产出再汇总 → 至少 L4。
- 降级原则：总分恰为区间下限（3/6/9）且无越级信号时，先按低一级设计并在假设清单标注升级路径，试跑不达标再升级；判 L4 前自问「单 agent 顺序执行能否胜任」，能则降回 L3。复杂度是成本不是荣誉。

## 边界案例

- 「帮我写个润色邮件的提示词」：S 全 0 → L1，零提问直接产出 + 假设标注。
- 「每天自动整理竞品新闻发我邮箱」：定时+发送 → S4=2，且属自动化循环场景 → 至少 L3。
- 「三个部门视角评审方案再汇总」：多角色独立产出再汇总 → L4，但先自问单 agent 顺序扮演三角色是否够用——一次性评审够用（降 L3），常态化流程才上 L4。
- 「把这份 PDF 里的表格转成 JSON」：S6=2 但 S1=0 → 总分低走 L1，配 schema 校验即可，不要过度设计。

## 级别 → 产出形态 → 策略装配

| 级别 | 产出形态 | 必装策略 | 按信号加装 |
|---|---|---|---|
| L1 | 优化提示词全文 + 一行使用说明 | 人设、明确性、结构化、正面引导 | 格式/风格特殊 → 少样本；S3=1 → 附验收标准段 |
| L2 | 步骤化 SOP（每步含目的/动作/提示词片段/检查点） | 同上 + 情境启动 | 有推理步 → CoT；S6≥1 → 输出格式化 |
| L3 | 提示链设计（环节表 + 数据契约 + 验证点 + 失败回退 + 内嵌闭环） | 提示链 + 验收标准先行 | S3=2 → 自我一致性或交叉核查；S4≥1 → ReAct |
| L4 | 完整编排（子 agent 分配表 + skill 清单 + 工具清单 + 主控循环与终止） | 多智能体 + 提示链 + 自我修正 | 探索型目标 → ToT；长期运营 → 文档化 + APE |

## 信号 → 策略速查表（构建与诊断精调共用）

| 观察到的信号 | 触发策略 | 一句用法 |
|---|---|---|
| 任何产出（基座，无条件） | 人设 + 明确性 + 结构化 + 正面引导 | 专家角色、量化边界、分隔符区分指令与数据、说「做什么」 |
| 任务常见、无特殊格式 | 零样本 | 直接指令，别堆示例 |
| 风格/格式难以言传 | 少样本 | 给 1–3 个高质量示例引导模式 |
| 有背景材料/上下文依赖 | 情境启动 | 背景信息前置并显式引用 |
| 需分步逻辑/计算 | 思维链 CoT | 「先逐步推理，再给结论」 |
| 客观有正解 + 错误代价中高 | 自我一致性 | 独立推理 3 次取多数 |
| 需实时信息/调用工具 | ReAct | 推理与工具调用交替，强制记录来源 |
| 需比较多个方案路径 | 思维树 ToT | 生成多路径→评估→回溯 |
| 思路僵化/输出表面化 | 退一步 | 先问抽象原则，再解具体问题 |
| 产出常有漏洞需自查 | 自我修正 | 内置「审查→改进」一轮 |
| 超 6 步或上下文会爆 | 提示链 | 拆环节，环节间只传显式产物 |
| 需多专业视角互相制衡 | 多智能体 | 各角色独立产出，汇总仲裁 |
| 初稿需人机协同打磨 | 建设性引导 | 对话式逐点修正，不推倒重写 |
| 下游程序消费产出 | 输出格式化 + 响应预填充 | 给 schema，预写回复开头锁格式 |
| 事实提取 vs 创意生成失衡 | 参数调优 | 低温取事实，高温取创意（环境支持时） |
| 输入超长「中间迷失」 | 长上下文优化 | 关键指令置尾、分块 + 提示链 |
| 任务涉及代码 | 代码提示 | 给上下文、报错原文、期望行为 |
| 提示词将长期复用 | 文档化 | 版本头 + 假设清单 + 变更行 |
| 关键任务需持续优化 | 自动提示工程 APE | 生成变体→评测→择优（成本高，慎用） |

策略的完整档案（核心思想 / 理想场景 / 何时慎用 / 组合建议）见 `strategy-map.md`。
