# Agent 路由说明

## 标书撰写

收到投标/标书/应答文件任务时：

1. 读取本目录 `SKILL.md` 作为角色、信条与流程
2. 先读 `素材库/`，再决定出不出确认卡（招标文件已能回答全部题、或用户说「直接做」→ 零提问）；招标文件放入 `招标文件/` 或由用户上传
3. 执行到环节 N 才读取 `prompts/环节N-*.md`，不要一次性读入全部
4. 交付模板查 `templates/`；成稿写入 `输出/`，命名 `<项目名>-标书-<日期>`
5. 用户说「复盘」→ 按 `复盘/复盘模板.md`（中标/落标/评审意见回填素材库）
6. 用户说「跑回归」→ 按 `回归测试/README.md` 对照历史中标标书自检
7. 无人上岗（运行 `上岗.sh`，或用户说「无人上岗」）→ 每轮一个新上下文：读 `验收清单.json` 与 `复盘/日志.md` 顶部「已知规律」，取第一个 `passes=false` 且依赖已通过的环节，只做这一个；产物落盘 `输出/`，逐条判验收项写回清单，追加日志一条；有 git 则提交 `feat: 环节N - 名称`。全部通过 → 输出 `<promise>交付</promise>`；闭环轮打钩数不增加或轮次到顶 → 输出 `<promise>止损</promise>` + 已达标部分 + 未达标清单 + 卡点报告；下一步是递交 → 输出 `<promise>待确认</promise>` + 确认卡后停下。分章撰写按章拆实例，每章一个上下文

红线（同 SKILL.md）：资质业绩只用素材库；废标项逐条打钩；报价留白由人定。
流程规则：应答矩阵不等确认，按 ★ 直接写；废标项存疑置顶警告但照常交付；全流程在无人回复时也要跑到三件套交付。

## 已知规律
从 `复盘/日志.md` 顶部抬升，改版时更新；只放跨项目都用得上的：
- 招标文件里的合同条款交给合同审查狗审，偏离表依据从其输出取
- 分章撰写按章拆实例，每章一个上下文，章节间只靠应答矩阵传递
