# 复盘（仓库级）

这里是 PromptDog 本身的复盘日志，不是某只工作狗的。规则与 `references/run-loop.md` 的「复盘两级制」相同：

- **日志**：一天一份 `YYYY-MM-DD-<主题>.md`，只追加不改写。记讨论脉络、结论、没定的事、产物链接。趁热写，写得快比写得全重要。
- **抬升**：日志里「下次做别的事还用得上」的规律，抬到它会被读到的位置——改行为的进 `SKILL.md` / `references/`，定方向的进 `design/`，对外可见的进 `CHANGELOG.md`。抬升后在日志里标一行「已抬升 → 文件」。

判断沉淀对不对只有一条：明天新开会话，把仓库丢给 agent，它不看聊天记录就能接着做。

## 回流表（交付物 → 资产）

只回流重复出现的事；触发者默认是人，在改版时做（★）。判断句：**同一规律出现 2 次即候选回流。**

| 交付物 | 变成什么资产 | 落到哪个现有文件 | 触发条件 |
|---|---|---|---|
| 澄清卡里被用户改掉的 ★ | 新候选，或 ★ 换位 | `references/clarify-cards.md` 行业候选库 | 同题被改 ≥2 次 |
| `验收清单.json` 反复不过的项 | 必带验收项 | `references/verification.md` 必带项表 | 同类型环节在 ≥2 只狗出现 |
| 止损卡点报告 | 诊断分支表新症状行 | `references/verification.md` 分支表 | 表里查不到该症状，且出现 2 次 |
| `复盘/日志.md`「已知规律」 | AGENTS.md 已知规律 | `kennel/<狗>/AGENTS.md` | 改版时（run-loop.md 已定） |
| 试跑样例 + 预期 | 回归样本 | `kennel/<狗>/回归测试/` | 每次交付随包，自动 |
| 用户原话 + 判级 + 产出形态 | evals 用例 | `evals/evals.json` | 判级被用户覆盖，或试跑不达标 |
| 流程图 JSON 的目标态 | 行业流程模板 | `references/clarify-cards.md` 候选库 | 同行业第 2 家验证 |
| 设计三件套 | 范例 | `design/` | 同类产品第 2 次出现 |
| 会话结论 | 规律 → SKILL / references | `复盘/YYYY-MM-DD-<主题>.md` | 每次会话趁热 |

不回流：一次性任务、环节 ≤2、单次细节（项目名、页码）。唯一例外：L3 一次性任务出现分支表没有的止损症状，追加一行到本目录当天日志。

回流本身的门槛：□ 改版的 CHANGELOG 有「回流来源」行 □ 新候选附来源狗与日期 □ 只加行不改结构
