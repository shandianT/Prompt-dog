## 结论

- **画布是中心，聊天窗口不是。** 工作台的主对象是流程图，工作狗是图的派生物。已抬升 → `design/workbench/产品定义.md`
- **两个建议的决定**：楔子 = 投标流程；运行模型 = 工作台是壳，引擎是用户自己的 Claude Code / Codex。已抬升 → `产品定义.md`（待拍板）
- **八条原则**是原型的判断标准。已抬升 → `SPEC.md` §3、`references/process-rebuild.md` 末尾
- **流程重构是 PromptDog 的一个入口模式**，不是判级对象：先出图与诊断，打包建议里的每只狗再判级。已抬升 → `SKILL.md` 入口路由、`references/process-rebuild.md`
- **流程图 JSON 是技能与画布的共同契约**：技能产出它，画布渲染它，复盘回流改它。已抬升 → `design/workbench/flow.schema.json`
- **设计文档 vs PRD**：设计文档定「画什么、怎么交互、按什么判断」，PRD 定「为谁、解决什么、怎么算成功、不做什么」。AI 时代留下的是：一页产品定义、可二值判定的验收、按依赖排序的小故事、状态文件；丢掉的是：长 PRD、评审会、事无巨细的原型标注。已抬升 → `产品定义.md`（一页）+ `stories.json`（可执行的 PRD）
- **「一句话 + 材料」**：一句话给方向，材料给现状；材料决定现状图八成质量，所以首页贴材料入口要醒目。已抬升 → `SPEC.md` §5 01 首页、`process-rebuild.md` 第 0 步
- **沉淀原则**：集合做日志（追加、趁热），分类做资产（按谁在什么时候读分，不按主题分）；判断标准是「明天新开会话，agent 不看聊天记录能接着做」。已抬升 → `复盘/README.md`

## 追加 · 设计模块与产品主线

用户追问：怎么保证每次都能输出高质量的设计文档和 PRD、配好看的图、画图技能怎么集成、设计模块作为导航项、交付物怎么回流提高 PromptDog、功能怎么协作与串并联、产品本身的一套流程。

做法：三位设计者（质量与评测 / 产品流程与系统 / 资产飞轮与协作）各出方案，三位评委按 七问 / 一致性 / 可判定 / 最短路径 / 可落地 打分。质量与评测方案胜出，嫁接另两份的：对抗审查四视角（老板 / 搭建者 / 执行者 / 反方，名字沿用产品定义角色表）、验收先于撰写、停机标记三值语义、交接表补三行、回流门槛三条、复盘用例。评委一致删掉的：卡片里的「图」题（档位由环境决定，转 H）、不能从 flow JSON 渲染的屏幕流图 / 状态机图 / 交接图、设计文档的「五个数字」首行（改为五问首行）、给未触发的回流预留段落。

结论与落点：
- 高质量靠机制不靠运气：范例（`design/workbench/` 三件套）+ 可打钩门槛 + 四视角对抗审查 + evals 回归。已抬升 → `references/design-mode.md`、`output-templates.md`「设计模式产物」、`verification.md` 必带项两行、evals 11–13

## 追加 · 开源选型：已有的功能都用现成项目

用户提出「可以参考 dify 的开源项目，同样的逻辑，已有的功能都可以用对应的开源项目」。三路并行调研（画布与编排 / 评测观测前端 / 生态与竞品），结论落在 `design/workbench/开源选型.md`。

三个最重要的发现：

1. **Dify、Langflow、Flowise 的画布底座都是 React Flow**（查三家 package.json 实证）。所以 fork 谁都等于背上一个我们不需要的执行引擎；直接依赖 `@xyflow/react`（MIT）就是站在它们同一个地基上。Dify 的修改版 Apache 2.0 另有两条硬伤：禁止用其源码运营多租户环境、用其前端必须保留其 LOGO 与版权——不能 fork 进 MIT 仓库再换品牌。n8n 的 Sustainable Use License 直接出局，ComfyUI 是 GPL，pm4py 是 AGPL，bpmn-js 把水印写进了许可证。已抬升 → `开源选型.md`、`产品定义.md` 已建议的决定、`stories.json` S01

2. **资产包不是差异化**。Agent Skills 已是开放标准（Anthropic 捐出，Apache-2.0 / CC-BY-4.0），最小要求就是 `SKILL.md` + name/description，可选 `scripts/` `references/` `assets/`——本仓库已经完全符合。AWS 的 `agent-sop` 也覆盖了同一块。继续把「我们的资产包格式」当卖点会被识破，应该改口径为「符合 Agent Skills 开放标准」，把兼容性当信任状。已抬升 → README、`开源选型.md`

3. **护城河要从资产包挪到流程重构**。ProMoAI（AGPL）、pm4aa、Celonis 这类流程发现全部依赖**事件日志**，而中小企业没有可挖的日志；闭源的 BaseFrame（YC W26）要连你的邮箱和会议。我们的「对话式采集 + 带 ★ 的选择题澄清」绕开了这个前提，且「流程诊断 → 卡点定位 → 生成资产包」这条完整链条在开源里是空的。BESSER-PEARL/agentic-bpmn 的 agentic lane + trust score 记号法可直接借来强化泳道图。

其余结论：evals 用 promptfoo（MIT、本地跑、`llm-rubric` 吃自然语言判据、`exec:` 可驱动 `claude -p`；OpenAI Evals 2026-11-30 关停且官方迁移路径就指向它）；观测不引平台（Langfuse 要四件套基础设施、Phoenix 是 Elastic License 2.0 非开源、Helicone 是代理形态），只对齐 OTel GenAI 语义约定的字段命名；前端 shadcn/ui + Tremor，都是复制源码不引框架；`上岗.sh` 不换（20 行零依赖，驱动的是业务验收项不是测试退出码），但要对齐 Claude Code 内置的 `/loop` `/goal` 并在文档里写明可零脚本替代。

## 追加 · 逐步交互规格

用户问能不能把「用户怎么用」的每一步都设计出来。之前有的是屏幕（14 块画板）和节奏（`使用逻辑.md` 第一周五步），缺的是中间那层：每一步的界面行为。补成 `design/workbench/交互流程.md` 与画布 12 用户旅程。

字段固定为八项：在哪屏 / 你看到什么 / 你做什么 / 系统做什么 / 产物 / 停在哪 / 不回复怎样 / 出错怎么办。主线十二步（0 安装 → 11 回到图上），另有六条异常路径（入口判错、材料不足、中途改主意、上岗止损、回归不达标、说「直接做」）。

写的过程中确认了一件事，之前散在各处没有汇总过：**全流程只有三个地方会停**——「按这个建」（无人时取楔子 ★ 继续）、人工确认点（不回复就一直停，是唯一不会自己往前走的地方）、「改版 / 不改版」（不回复就不改版）。其余每一处分叉都有 ★ 默认路径。这就是「卡片是纠错窗口，不是审批关卡」在界面上的完整含义，已作为停机总表写进文档末尾。

## 追加 · 每个功能每一步：画出来、拆成组件、逐步评审

用户要的三件事：每个功能每一步都画出来；形成组件模块化、开发能复用；画每一步时判断哪里合理、哪里缺、哪里没用，整条逻辑要顺。做法是先评审后画：`逐步评审.md` 把七个功能 40 步逐步过一遍，每步三栏（合理 / 缺少 / 没用）加一栏决定，再按决定画屏、删屏、改屏。

评审的收获比画本身大：

- **缺的多数是「状态」不是「屏」**。原来 15 块画板覆盖了功能，却几乎都只画了一个瞬间；生成中、生效后、运行中、完成、止损、空态这些状态一个都没有，而用户恰恰在这些状态里等待和判断。补的 20 屏里 16 屏是状态。
- **两条整条断掉的线**：诊断（贴提示词）一屏都没有；侧栏「组件库 12」有入口没有页。都是「先做大头」时被顺手略过的。
- **没用的东西都是「说给用户听」而不是「给用户用」的**：四道保险绿勾、重复的提示卡、给脚本看的 promise 标记、老板屏上给 IT 的按钮。删掉后每屏的主按钮都对准了那一步的唯一动作。
- **规格与原型的两处脱节**在画静态状态时暴露：n12 受保护只写在规格里，原型没实现；应用建议后数据节点会跳出数据泳道。都改了。「试跑」也是这一类——名字暗示画布能跑，改成「运行态」并真的去读 验收清单.json。
- **状态机对账**是最便宜的整体检查：列出每屏的出口，三个停机点没有变多，「一个数字只有一个来源」也守住了。

组件化落成两层：Sidebar / Topbar / InputBar / FlowNode 是可传参的真组件（画布用 `<dc-import>` 引用，改一处所有屏跟着变，已在编辑器里验证）；其余 12 个组件每个一张状态表，每一块由生成屏幕的同一个 Python 函数产出，所以屏幕和组件表不会漂移。`组件清单.md` 把 props、状态、用在哪些屏、用什么开源件承接写成表，开发按表建组件即可。

工程上一个小决定：静态截图不经过编辑器，所以生成器有 `--inline` 开关——同一份函数既能输出 dc-import 版（给画布），也能输出内联版（给无头 Chromium 截图）。两份不会漂移，因为它们是同一段代码。
